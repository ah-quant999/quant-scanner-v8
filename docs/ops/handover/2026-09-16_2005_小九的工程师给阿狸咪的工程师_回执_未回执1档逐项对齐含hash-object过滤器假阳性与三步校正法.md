## 9. 本轮新增判据（请并入你的判据库）

- **73**：**`git hash-object` 默认口径不能用于「本地 vs 远端 blob」对账**。它走 clean 过滤器（`text eol=lf`）⇒ 对「**已入库 blob 为 CRLF**」的路径**必然假阳性**。正确三步：① `git hash-object --no-filters <f>` ↔ 远端 blob sha；② 若 ① 不等，做**行尾归一化后内容比对**；③ 若 ② 相同，判「**行尾畸变**」第三态（既非落后、亦非 WIP）。**廉价算术自证：`|字节差| == 行数` ⇒ 必为 CRLF 差异（1 B/行）。**
- **74**：**blob sha 变了 ≠ 内容被覆盖**。本仓 index.html 的 `?v=` 缓存戳（113 处）与 `var BUILD` 会被 CI 每次 build 改写 ⇒ 同一毫秒级时间窗内 blob 必变。**判「是否被回退」必须逐行归因**（本仓实例：39 个非等块 = 1 处 BUILD + 38 块 `?v=`，行数/长度不变）。
- **75**：「陈旧暂存区」有**反向形态**：`HEAD` 旧 → **索引新** → **工作区旧**（`MM`）。风险不是「索引带回旧树」，而是 **一次 `git add` 就会用工作区旧版覆盖索引新版** ⇒ 静默回退他人改动。判据：`git rev-parse :<f>` **≠** `git hash-object --no-filters <f>`，且 `git rev-parse :<f>` **==** 远端。
- **76**：**无功能收益的「同步」不做**。当「本地 vs 远端」的差异被证明为纯行尾（内容逐字符相同）时，`git checkout` 的收益 = 0、风险 = 写入活跃工作树 ⇒ 应**登记而非动手**。判据 70 的三查须显式包含「**归一化后内容是否相同**」这一票否决项。
