- `v8_ima_strong_stock.yml` **09-18 两跑全红**（`07:51Z` workflow_dispatch、`12:22Z` schedule），

### 5.2 根因 = **判据 114（注释即规格）违规 —— 护栏比规格更严**
- 脚本自身 L164 注释（我 09-18 07:08 提交 `be2837a8d400` 时写的规格）明说：
  「修复后 first_selected **112/112**，缺失归 0（**仅剩 2 条真实无价的记录**）」；
- 而 L415-417 护栏写 `if parse_health.get("field_missing_counts"): 拒写`（**恒 0 才放行**）；
- 叠加**语义漂移**：`_take_field` 对**空串是消费指针**，故一次 miss 的含义已从「串位」
  变成「该格**非空**但非预期类型」—— 正是「无报价」的形状，旧文案已失效。
⇒ **规格说允许 2 条，护栏说必须 0 条** ⇒ 自相矛盾，护栏错。上线后**首跑即把整条链打死**。

### 5.3 修法（`2f8707cd3171`，blob `7e4494ae6c8b`，21594 chars，逐字节一致 ✅）
1. **留原始 token 证据**：`missvals[field] = lines[j]` → 产物 `field_missing_samples`；
2. **抽纯函数 `classify_residue()`** 做分级（可被回归用例直接调用，不必「跑整条 CI 才知道对不对」）；
3. **良性也不静默**：写入 `parse_health.no_price_records / no_price_codes` + 打印醒目 warn。

**分级判据（全部满足才算良性）**：① 缺失**只有**那四条价格字段（任何结构性字段缺失 ⇒ 红）；
② 四条**缺失条数完全相同**（不同 ⇒ 各自串位 ⇒ 红）；③ 缺失数 ≤ `max(2, 5%)`（超 ⇒ 列序变了 ⇒ 红）。

**回归用例 6/6 通过**：CI 实测形状（各缺 2 / 总 112）⇒ 放行 ✅；修复前形状（72 条六字段塌陷）⇒ 红 ✅；
