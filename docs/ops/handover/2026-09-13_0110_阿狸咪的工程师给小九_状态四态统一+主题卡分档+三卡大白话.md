## 二、核心根因（三层，全部已修）

### 🔴 第 1 层：前端 `skip` 误判为红灯（诉求③的直接原因）

`index.html` 的「数据健康总览」`renderRunnerTrack` 里，模块灯色只有三态判定：

```js
// 修复前（错）：skip 落进红分支
const color = m.status === 'ok' ? 'var(--down)' : (m.status === 'empty' ? 'var(--gold)' : 'var(--up)');
```

而 `RUNNER_STATUS` 的 `status` 实为**四态**。实测远端数据：

```
summary = {"total":1,"ok":1,"empty":0,"fail":0}   ← 汇总说 0 失败
_module_total = 73, _module_run = 1                ← 73 个模块只跑了 1 个
status 分布 = {"skip": 72, "ok": 1}                ← 72 个是 skip
skip 的 msg 原文 = "本周期未运行（未出现在 runner_status）"   ← 语义明确是正常分批
```

⇒ **汇总说 0 失败、明细却整片飘红 = 渲染 bug，不是故障。**

**修复**：新增统一映射函数并与「任务运行看板」同源（该处 L11095 本来就是正确的四态实现）：

```js
function _stColor(s){
  if(s === 'ok') return 'var(--down)';                                   // 绿
  if(s === 'empty' || s === 'warn') return 'var(--gold)';                // 黄
  if(s === 'skip' || s === 'stale' || s === 'limited') return 'var(--dim)'; // 灰
  return 'var(--up)';                                                     // 红
}
```

另补**「灯色图例」**说明块，主人可自行判断红/黄/灰语义，不用再问「是不是完蛋了」。

### 🔴 第 2 层：`manual_dep` 语义污染（诉求⑤「一劳永逸」最深一层）

`v8_health_check.py` 的 `CARD_DEFS` 里，`manual_dep: True` 表示「人工维护卡」。实测 8 个条目里**6 个是错标**：

| 条目 | 真实性质 | 原标记 | 现标记 |
|---|---|---|---|
| `MACRO_DATA` 今日宏观解读 | 主人撰写 | `manual_dep` ✅ | `manual_dep`（保留） |
| `UNLISTED_PANEL` 暂未上架索引 | 主人推送 | `manual_dep` ✅ | `manual_dep`（保留） |
| `FACTOR_LAB` 因子实验室 | 本机 baostock 黑名单 → 需小九 | `manual_dep` ❌ | **`net_dep`** |
| `RPS_BACKTEST` RPS A档回测 | 同上 | `manual_dep` ❌ | **`net_dep`** |
| `STOCK_STOP_DATA` 精确止损止盈 | 本机 gtimg WAF → 需小九 | `manual_dep` ❌ | **`net_dep`** |
| `H_AUTO_BUY` H反推 | 同上 | `manual_dep` ❌ | **`net_dep`** |
| `H_AUTO_BUY_TRACK` 追踪 | **已恢复产出** | `manual_dep` ❌ | **（移除）** |
| `DO_NOT_DELETE` 防误删清单 | 脚本周日自动生成 | `manual_dep` ❌ | **（移除）** |

**污染后果链**（这就是状态漂移的真凶）：

```
标成 manual_dep → 陈旧时走 status = 'limited'
  → 本机跑的旧版生成器无 limited 概念，只能判 'warn'
  → 同一份数据在两台机器判出两个不同状态（warn ↔ limited 漂移）
  → 前端「失败/诊断详情」此前只放过 ok，limited/warn 全被当失败推入 → 主人看到的假告警
  → 且面板文案写「待主人手动更新」，实际在等你的机器，误导人工介入
```

**修复**（4 处，改动面已列全）：
1. `CARD_DEFS`：6 项错标修正（5 项降级为 `net_dep`、1 项移除）
2. 跳过 raw_data 自救的条件：`manual_dep` **或** `net_dep`（行为兼容，不误派发自愈任务）
3. 状态映射：`manual_dep`→`limited`（🔒 等主人）/ `net_dep`→`warn`（⚠ 等小九，非故障）
4. 汇总口径注释明确：`overall` 仅由 `fail` 决定，`warn`/`limited` 不拉低健康度

### 🔴 第 3 层：前端诊断过滤把 `limited`/`warn` 当失败（诉求④⑤）

```js
// 修复前：只放过 ok
if(!it || it.status === 'ok') return;
// 修复后：四态语义
if(!it) return;
if(it.status === 'ok' || it.status === 'limited' || it.status === 'warn') return;
```

⇒ RPS A档回测（`limited`，受限可用、有降级数据）不再占据运维诊断位；其信息已归位到 RPS 卡自身的新增「📡 数据口径说明」块。
