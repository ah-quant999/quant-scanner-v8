# v8 选股评分正交化重构方案（2026-08-29）

## 1. 问题诊断

### 1.1 核心结论：评分没有区分度
`alpha_vs_beta_report.json` 显示：
- TOP1/3 评分组 T+10 超额 **+7.89%**，超额胜率 79.1%
- BOTTOM1/3 评分组 T+10 超额 **+8.17%**，超额胜率 58.0%
- 两者超额均值只差 **0.008pp**，说明**打分排序几乎无法区分未来收益**

### 1.2 因子 IC 揭示的失真（`factor_ic_report.json`）
| 因子 | T+10 IC | 含义 |
|------|---------|------|
| `pct_chg_20d` | **-0.293** | 20日涨幅越高 → 未来10日收益越低（动量反转） |
| `score_quality` | **-0.071** | 基本面质量分越高 → 未来收益越低 |
| `score_base` | -0.025 | 基础分越高 → 未来收益略低 |
| `total_score` | +0.140 | 总分有微弱正预测力 |
| `sig_count` | +0.276 | 信号数量越多 → 未来收益越高 |
| `score_form` | +0.097 | 形态分有弱正预测力 |

**关键发现**：当前评分体系把「质量 A 级」和「20日强势」当作加分项，但数据证明它们与未来收益**负相关**。这是评分区分度崩溃的直接原因。

### 1.3 多基准检验：超额里有多少是 beta？
新增上证/中证1000/国证A指三基准后：
- T+10 个股均收 +7.46%
- 相对上证超额 +5.72%，相对国证A指 +4.53%，相对中证1000 +2.22%
- **约 3.5pp 的「超额」实质是小盘风格 beta**；真实选股 alpha 约 2~4.5pp

## 2. 重构目标

1. **正交化**：把高度同源的评分维度拆成 5 个独立信息源
2. **去伪**：移除/降权与收益负相关的因子（质量分、20日涨幅）
3. **增信**：放大与收益正相关的因子（信号数量、形态、资金流/机构真实有效时）
4. **可解释**：每个源单独可回测、可退役
5. **保留接口**：前端 `total_score` 与阈值语义不变（≥80 精选 / ≥70 观察）

## 3. 五独立源设计

### 3.1 源一：价量突破（Weight 35%）
- 输入：5日突破、20日平台突破、量比、RS 相对强度
- 依据：`sig_count` 与 `score_form` 是当前唯一有正 IC 的内部因子
- 处理：
  - 5日突破信号 +30 分
  - 20日平台突破 +15 分
  - 量比 ≥1.5 +10 分
  - RS 前 25% +10 分
- **反向规则**：20日涨幅 ≥35% **扣分**（IC=-0.29 的反转证据）

### 3.2 源二：基本面质量（Weight 10%，降权）
- 当前 A 级 +40 分导致高质股被过度买入，反而跑输
- 改为：A 级 +5 / B 级 +2 / C 级 0 / D 级 -5
- 目的：仅作风险过滤，不做收益增强

### 3.3 源三：资金流/机构（Weight 20%，但需先修复数据源）
- 当前 `score_fund`/`score_inst` 非零率仅 0.8%/3.2%，几乎无效
- 必须先修复 `capital_flow_data.json` / `lhb_data.json` 的读取路径
- 修复后：北向净流入 +10、龙虎榜机构净买 +10、板块资金前 5 +10
- 若数据源缺失，该源整体置 0，不硬编

### 3.4 源四：情绪周期（Weight 20%）
- 输入：涨停热度、 crisis 雷达、市场涨跌家数、波动率
- 仅在「情绪冰点/修复初期」加分，过热期扣分
- 与 CRDS 逆势龙头联动

### 3.5 源五：宏观/行业景气（Weight 15%）
- 输入：行业 RS 排名、sector_rs、宏观经济状态（regime）
- 避免全市场无差别打分

## 4. 关键改动清单

### 4.1 `algorithms/generate_top10.py`
- 把 `score_*` 维度按五源分组
- `pct_chg_20d` 从「涨幅越高加分越多」改为「涨幅过高扣分」（反转因子）
- `score_quality` 大幅降权
- 每个源输出独立字段：`source_price`、`source_fund`、`source_sentiment`、`source_macro`、`source_quality`
- 总分 = 加权和 / NORM_DIVISOR × 100，保持 0~100

### 4.2 `algorithms/factor_ic_analysis.py`
- FACTORS 列表增加五源字段
- 输出每个源的 IC 与分层，便于持续监控

### 4.3 信号退役机制
- 每月 1 日自动跑 `factor_ic_analysis.py`
- 若某源连续 30 天 |IC_T10| < 0.03 或 IC 与预期方向相反，自动权重减半
- 连续 60 天无效则权重置 0，前端显示「该源已暂停」

### 4.4 前端 `index.html`
- 逻辑详解页增加「五源评分架构」说明
- 三重共识卡片展示每个源灯（绿=正贡献/灰=无/红=负贡献）

## 5. 验证标准

1. `factor_ic_report.json` 中 `score_quality` 与 `pct_chg_20d` 的 IC 转正或接近 0
2. `alpha_vs_beta_report.json` 中 TOP1/3 与 BOTTOM1/3 的 T+10 超额差距 ≥ 2pp
3. 相对中证1000 的 T+10 超额稳定在 ≥2pp
4. 全样本 T+10 胜率保持 ≥60%

## 6. 实施顺序

1. **P0**：修复资金流/机构数据源路径（`score_fund`/`score_inst` 当前几乎全 0）
2. **P1**：在 `generate_top10.py` 中实现五源框架 + 质量分降权 + pct_chg_20d 反转
3. **P1**：更新 `factor_ic_analysis.py` 监控五源
4. **P2**：建立月度自动退役机制
5. **P2**：前端展示五源灯

## 7. 风险

- 大幅改权后历史回测口径会断裂，需同步重跑 `renormalize_top10_history.py`
- 数据源未修复前，源三（资金流）仍无效，权重不宜过高
- 20日涨幅反转只在当前 3 个月样本中验证，需持续观察
