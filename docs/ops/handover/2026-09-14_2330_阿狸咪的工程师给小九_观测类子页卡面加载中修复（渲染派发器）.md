## 一、🔴 真根因（真浏览器实测复现，非推断）

### 1.1 现象

| 进入方式 | 观测类 3 卡 | 大盘观察 3 卡 |
|---|---|---|
| 直接进「暂未上架」（默认落在**观测类**） | ❌ 主题空间 / AI洞察 =「加载中…」 | — |
| 点「📊 大盘观察」 | — | ✅ 3 卡全部正常（艾略特卡 14,828 字符真实渲染） |
| 点「📡 观测类」 | ❌ 仍是「加载中…」 | — |

实测证据（agent-browser 真 Chromium，控制台 0 报错）：

```
switchSec('ul') 后等 40s：
  elliottWaveBody=430  themeValueBody=102  aiInsightsCompareBody=101
  citicPeObserveBody=97  indexObserveBody=95  dbgEtfMapBody=5623   ← 只有 ETF 卡出来了
  elliottWaveBody 文本 = "📊 艾略特波浪 · 深度分析…加载中…"
点 __ulSwitch(btn,'market') 后：
  elliottWaveBody=14828  citicPeObserveBody=6736  indexObserveBody=5094   ← 立刻全出
```

### 1.2 两条独立成因（叠加才导致「永久」）

1. **`_renderPostReady()` 只跑一次，且跑得太早。**
   它挂在 `DOMContentLoaded`（+`setTimeout 30`）。那一刻 `unlistedPanel` 还是**空壳**
   （`innerHTML.length === 0`，实测），5 张卡的渲染函数全部撞上
   `var dst = document.getElementById('…Body'); if(!dst) return;` ——
   **且这句判空写在各自的重试逻辑（`__tvRetry/__aicRetry/__cpeRetry/__ivpRetry/__ewRetry`）之前**
   ⇒ 连重试都没布上，直接静默返回。
2. **`__ulSwitch` 的 observe 分支是空块。**
   ```js
   if(tab==='observe'){
   }                      // ← 空！
   if(tab==='market'){ …3 个渲染调用… }
   ```
   ⇒ 用户切到观测类时无人叫渲染函数。而默认进入就是 observe，所以**一进去就是空卡**。

> 两条叠加 ⇒ `renderUnlisted()` 只建骨架、`_renderPostReady()` 永不再跑、observe 分支空
> ⇒ **三处都没人叫渲染函数** ⇒ 卡面永久「加载中…」。

## 二、修法（一劳永逸，不搞特立独行）

新增单一真源 **`window.__ulRenderPane(tab)`**，两个子页共用同一套派发逻辑：

```js
window.__ulRenderPane = function(tab){
  tab = tab || window.__ulActivePane || 'observe';
  var names = (tab==='market')
    ? ['__renderElliottWave','__renderCiticPeObserve','__renderIndexObserve']
    : ['__renderThemeValue','__renderAiInsightsCompare'];
  var probe = document.getElementById(tab==='market' ? 'elliottWaveBody' : 'themeValueBody');
  if(probe) probe.setAttribute('data-ulpane', tab);       // 幂等标记
  …逐个 typeof 守卫 + try/catch 调用，返回 'k:ok,k:nofn' 供肉眼核…
};
```

三处挂载：

| # | 位置 | 作用 |
|---|---|---|
| ① | `window.__ulSwitch` 的 observe / market **两个分支**统一改为调派发器 | 修「点 tab 不渲染」；顺带消掉 observe 空块 |
| ② | 已有的 1.5s `__ulSelfHealTimer`，在「骨架就绪」停止分支派发一次当前子页 | 修「默认首次进入不渲染」（无需猜延迟，复用它原有的轮询） |
| ③ | `data-ulpane` 幂等标记 | 防每 1.5s 重渲刷屏（主题空间单卡 56KB innerHTML）；`renderUnlisted` 重建 DOM 会丢标记 ⇒ 自动再派发 |

### 为什么不改那 5 个渲染函数？

它们各自的重试预算只有 `20~25 × 400~900ms`（≈8–22s）。把 `dst` 判空改成「布重试」
只能覆盖「页面加载后 20s 内被打开」这一种时序，**仍然漏掉**主人「过一会儿才点进去」的主路径
⇒ 不是一劳永逸。派发器是**确定性**的：DOM 一就绪就派发，与耗时无关。

## 三、我为什么不认为这是「小九的锅」也不认为是我上一轮漏了

- 「观测类 / 大盘观察」双子页拆分**是今晚新加的**（主人 2026-09-14 令），
  拆分时 observe 侧只剩 1 张 ETF 卡（`dbgEtfMapBody` 由 `renderUnlisted` 内联渲染，不需要派发）
  ⇒ 空块在当时**不产生可见症状**，是个潜伏 bug；
- 我上一轮补回 2 张卡（卡容器 + 渲染函数 + 数据注入三件齐）**逻辑上是对的**，
  但把「观测类变 3 张」这个前提激活了 ⇒ 潜伏 bug 才暴露。
- **教训（建议沉淀）**：拆子页 / 新增卡的渲染函数，凡是依赖 `_renderPostReady()` 在页面顶部调度的，
  都必须同时挂到**子页进入路径**上；`dst` 判空不应写在重试逻辑之前。
