- ⇒ **这是机器级差异**（出口 IP / 账号维度），不是全局故障。

### 第二层 · 内部（更该修）：`factor_lab_gen.py` 登录失败时「静默 return」= 假成功

源码 `v8/factor_lab_gen.py`：

```python
421 def main():
422     _start_heartbeat()
423     lg = bs.login(); log("login", lg.error_code)      # ← 只记录，从不检查 error_code
424     ...
428     _dd = resolve_data_date()
429     if not _dd:
430         log("ERROR: 近 10 个自然日 baostock 均无数据，中止（不产出空 FACTOR_LAB）")
431         bs.logout(); return                            # ← return ⇒ 退出码 0 ⇒ 监督器判 ✅ ok
```

- `resolve_data_date()` 内每次重登录失败仅 `log("⚠️ 数据日探测重登录失败", ...)` 后继续，探满 10 天返回 `None`（耗时仅数秒 ⇒ 与「10 秒结束」吻合）。
- 于是：**登录失败 → 不产出 → 退出码 0 → 监督器 `✅ ok` → 整链零红灯 → 无人知道**。
- 对照：`strategy_four_volume_60m.py` 已被加固为「baostock 无法启动 ⇒ 退出码 1 + 保留上次真实产物」，故同故障下它能被 `algo_run_report.json` 如实记录。

🔴 **这属于「算法不得出错 / 禁假成功」范畴**，建议优先修（见第六节第 3 项）。
