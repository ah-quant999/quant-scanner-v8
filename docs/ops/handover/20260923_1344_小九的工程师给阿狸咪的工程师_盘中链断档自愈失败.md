## 二、根因（已定位到行，非调度问题）

### 2.1 直接证据（run `35821028940` 日志原文）

本轮 13:00 档的云端抓取 run **status=success**，但日志里：

```
>>> CONCEPT_RANKING 2026-09-23T13:20:45+08:00
  ⚠️ CONCEPT_RANKING: 返回空，跳过
```

```
[FAIL] 实时数据/概念排名: 更新于 今日 11:28；超过阈值 45 分钟
⏭️  CONCEPT_RANKING 数据未变，跳过重写（幂等）
✅ concept_ranking.json → CONCEPT_RANKING.js
```

即：**抓取层拿到空数据 → 跳过 → `raw_data/concept_ranking.json` 未更新 → 重生成层幂等跳过 → `data/CONCEPT_RANKING.js` 永久冻结。**

链路**自带红字告警**（`[FAIL] … 超过阈值 45 分钟`），但该步属**软失败**、不阻断 run ⇒ **run 报 success，数据却零推进**。这正是本任务根因背景里所说的「假成功」。

### 2.2 病灶代码（`cloud_fetch_v8.py` L1996-2010）

```python

    rows = em_clist("m:90 t:3 f:!50", "f12,f14,f3,f62,f184,f20", fid="f62", stat="1", pz=300)
    items = []
    for r in rows:
        ...
    if not items:
        return None
```

- **数据源唯一**：`push2delay.eastmoney.com` 的 `m:90 t:3`（概念板块列表）。
- **无备选源、无重试**（对比同文件 `f_candidate_quotes` 有 3 次重试 + 退避）。
- `em_clist` 对网络异常**静默吞掉并返回空列表** ⇒ 上层无法区分「源站故障」与「真的没有概念板块」，一律走 `return None` ⇒ 表现为「返回空，跳过」。

## 三、为何三级 dispatch 全部无效

三个 dispatch 目标（准点档调度器 / 云端中国数据抓取 / 小九应急链）**只是「让抓取链再跑一次」**。
但 `f_concept_ranking()` **本身拿不到数据**（源站拒连）⇒ **重跑 N 次结果一样为 `return None`**。

⇒ **这是「重试不可救」型故障：故障点在数据源，不在执行链。** 阶梯自愈设计对这类故障天然无效。
