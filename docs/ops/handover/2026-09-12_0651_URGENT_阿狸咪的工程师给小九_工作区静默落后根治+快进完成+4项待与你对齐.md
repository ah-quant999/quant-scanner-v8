**绝不能只看 `git status`**。


⚠️ 别用「逐个 `git show` 循环扫 3900 文件」——每个文件 fork 一次 git，实测 3.6 分钟不出结果。
`git diff --raw` 一次调用拿全量，秒级。

### 坑 2｜`git diff --raw FETCH_HEAD` 的 `[删]` 多是「远端新增」不是「被删」

基准是远端，所以「远端有、本机 HEAD 不知道」的文件会被打成 **`D`（删）**。
**判据（三态，必须全查）**：

```bash
git cat-file -e "HEAD:<path>"       && echo "HEAD有" || echo "HEAD无"
git cat-file -e "FETCH_HEAD:<path>" && echo "远端有" || echo "远端无"
[ -f "<path>" ]                     && echo "磁盘有" || echo "磁盘无"
```

- **HEAD 无 / 远端有 / 磁盘无** → **是远端新增，不是我落后** ✅ 正常，**禁报成坚果云删文件事故**。
- **HEAD 有 / 远端有 / 磁盘无** → 真·坚果云删除，立即恢复。

我实测 12 个「物理缺失」**全部是第一种**（`scripts/v8_delist_advice.py`、`data/CANDIDATE_QUOTES.js`、
`backup/raw_data_backup_20260912_0201.tar.gz`、7 份交接稿、3 个 raw_data 历史文件）。

### 坑 3｜`git checkout -- .` 会**误重置索引**（我踩了）

快进后我想追齐磁盘，跑了 `git checkout -- .` → **把索引重置成旧状态**（157 项 `M ` 暂存区差异）。
`git status` 里字母在**第 1 列**（`M `）就是「已暂存」的信号，不是工作区改动。

**正确姿势**：`git restore --source=HEAD --worktree -- .`（**明确指定 source**，不依赖索引）；
或 `git checkout HEAD -- <path>`（带 `HEAD` 才不走索引）。修索引用 `git reset -q HEAD`（只动索引、不碰磁盘）。

### 坑 4｜`index.html` 的 CRLF 假差异（14961 B）

`index.html` 在 `.gitattributes` 里**没有 eol 规则**（而 `*.py` / `*.yml` 是 `text eol=lf`）。
坚果云把 index.html 的 LF 全改写成 **CRLF → 凭空多 14961 字节**（磁盘 1083495 vs HEAD 1068534）。

**澄清**：这不是内容差异！行尾归一后**逐字节一致**。

```bash
tr -d '\r' < index.html | cmp -s - <(git show HEAD:index.html | tr -d '\r') && echo "纯行尾差异"
```

→ **判 `index.html` 是否真差异，必须先归一 CRLF 再比**，否则会被 14961 B 的假差异骗到。
（同理：`*.py` / `*.yml` 磁盘是 CRLF 但被 `.gitattributes` 自动归一 → `cmp` 报 ❌ 而 `git status` 干净。
**`git status` 干净 + `cmp` 报差异 = 行尾假象**，这是判据。）
