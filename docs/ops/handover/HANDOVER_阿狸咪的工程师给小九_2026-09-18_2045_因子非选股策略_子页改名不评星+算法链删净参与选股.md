### 3.2 关键机制：为什么 `ensure()` 就是"参与选股"

`final_recommend.py` L704 的 `ensure()` 内部第一句是 `r = pool[_nc]`，而 **`pool` 是 `defaultdict(工厂函数)`**（L700 结尾可见）。
⇒ 对**不在池内**的票，`pool[_nc]` 会**新建一条空记录并留在池内**。
⇒ 因子榜 TOP30 × 2（异常换手率 + ROE_TTM）**逐只走 `ensure()`** ⇒ **等于让 60 只因子票无条件进入最终推荐候选集**。

这不是"加分"，这是**因子在决定谁能进池**。

而 L1384 那段 `_factor_extra` 更直白，其原注释自述：

> 「方案B：因子候选（异常换手率/ROE_TTM）因权重低常落在 top30 之后，**需强制纳入候选池**，否则方案B不可见」

⇒ **因子不仅能让票进池，还能把已经排在池外的票捞回池内**。

### 3.3 修复（删净两处）

1. **新增 `_factor_in_pool(code)` —— 只查不建**：
   ```python
   def _factor_in_pool(code):
       return norm_code(code).lstrip('.') in pool
   ```
   ⚠️ **探测绝不能用 `pool[_nc]`** —— defaultdict 取值会**创建空记录**，那正是本判据要禁的"进池"。
2. 两个因子循环在 `ensure()` **之前**插入 `if not _factor_in_pool(code): continue`
3. `_factor_extra` **整体删除**；产物输出由 `(_top30 + _factor_extra)` → `_top30`

### 3.4 改后因子还剩什么（"只做加减分"的真实边界）

- **异常换手率**：命中 ⇒ 写 `tags`（仅展示）。⚠️ 09-18 改动 2a 已因**负 alpha（边际 −2.21pp，命中 85 条）**把它整源剔出 `sources` ⇒ **它当前不加分**；但仍保留 **放量弱势 −0.5 扣分**。
- **ROE_TTM**：命中且**已在池内** ⇒ `source_scores` **降档加权**（1.0 / 0.75 / 0.5；非开仓期 ×0.3）。
- **P5 两因子（amt60 / turntrend）**：候选池内分位前 20% ⇒ +6、20~40% ⇒ +3；**只在 `verdict=PASS` 时启用**。

⇒ 三者的共同点：**只作用于"已被其他源选出来、已在池内"的票**，不再影响"谁能进池"。
