## 一、真因 ①：GBK runner 上 UTF-8 无 BOM 的 `run:` 块解析失败

### 机制（字节级）

cn runner 是 Windows，系统码页 **GBK(936)**；GitHub Actions 把 `run:` 落成临时 `.ps1`，编码是
**UTF-8 无 BOM**；Windows PowerShell 5.1 对无 BOM 脚本**按 ANSI(GBK) 解码**。解码规则下，
多字节字符的**尾字节会吃掉紧随的一整个字节**（引号 `0x22`、换行 `0x0A` 都落在 GBK 合法尾字节区间
`0x40–0xFE` 之外，解码器把该 2 字节对整体替换）。

后果分两级，**第二级更危险**：

| 被吃掉的字节 | 后果 | 是否报错 |
|---|---|---|
| `"` | `ParserError: 字符串缺少终止符` | ✅ 会红 |
| 换行 `0x0A` | **下一行代码并入上一行注释 ⇒ 整条语句凭空消失** | ❌ **零报错、零红灯** |

### 实证（本机即 alimi-cn runner，结论可原地复现）

- `v8_dajijin_fetch.yml` 4 个 run 块：修复前 PowerShell 5.1 解析错误数 **2 / 3 / 0 / 2**。
- **CI 侧原始证据**：run `36006148888`（#1）与 `36034611514`（#2）**均**
  `FAILED STEP #2 📝 同步源码`，报 `ParserError … TerminatorExpectedAtEndOfString`。
- **静默吞行实测**：step2 原文 8 行，`GetEncoding(936).GetString()` 后**只剩 7 行** ——
  `$out = python scripts/dajijin_need_push.py 2>&1 | Out-String` **整行并入上一行注释**
  ⇒ `$out` 恒 `$null` ⇒ `need=0` ⇒ **即便解析通过也永远不推送**。
- step0 同法 29 行 → **27 行**。

### 修复

`v8_dajijin_fetch.yml` 三个 run 块内 **10 行中文**（注释 / `Write-Host` 日志 / 提交信息文案）
ASCII 化，**代码逻辑零改动**（用 `CommandAst.GetCommandName()` 有序序列比对为证）；
中文原文**无损保留**为文件尾部 YAML 注释块（YAML 由 GitHub 按 UTF-8 读、**不经 PowerShell**）。
提交 `86a7f056a1e9`（parent `51ad156adb13`，blob `02299413152a`）。

### 铁证

```

→ MAHORO_COOKIE(2026-08-08) / V8_GH_TOKEN(2026-08-05) / ZSXQ_TOKEN(2026-08-17)
```

**没有 `GH_PAT`。** 而全仓只有两条 workflow 引用它 —— 正是这两条单飞链。
模板解析为空 ⇒ `'Authorization' = "Bearer $env:GH_PAT"` 变成 `Bearer `（空）⇒ 401。

**而该 run 的结论 = `success`。** 这就是「假绿」的教科书样本。

### 两条链各自的假绿形态（这决定了它为什么能藏这么久）

- **dajijin**：step0 三步全 401 后退化为**使用 runner 工作区里的陈旧本地副本**（`Test-Path` 守卫
  被旧文件骗过，`exit 1` 不触发）；step3 的 `api_put_file.py` 读 `GITHUB_TOKEN`/`GH_TOKEN` 亦为空
  ⇒ `exit 1` ⇒ 但 `continue-on-error: true` + 内部只 `Write-Host` ⇒ run 仍 success。
  产物 `data/DAJIJIN_REDUCTION.js` 自 **2026-09-23 19:43 冻结 2 天**。
- **lhb**：step0 同步 401 后退回本地副本（脚本自述 `using local copy (LHB may be stale)`）；
  step3 跑 `python api_push_raw.py --only lhb` 但**整个 step 无 `env:`** ⇒ `api_push_raw.py` L33-35
  取不到 `GITHUB_TOKEN`/`GH_TOKEN` ⇒ `❌ 缺少 GITHUB_TOKEN; sys.exit(1)` ⇒
  被 `|| Write-Host "api_push_raw failed, non-blocking"` 吞掉 ⇒ **run 恒 success**。
  （线上龙虎榜由主链 `v8_cn_fetch_cloud` step10 供给，所以这条链长期假绿也没人发现。）
