## 二、根因（CI 日志实证，非推测）
**不是没抓，是 raw_data 抓到了、data/*.js 没重生成 —— raw→JS 断链。**

- 远端 `raw_data/market_fund_flow_data.json` = **15:22:49**（post_close 档 step8 已抓取刷新）
- 但 `data/MARKET_FUND_FLOW_DATA.js` = **14:20:10**（前端展示的旧值）

查 post_close 档 run `34449540052` step20(update_v8) 日志，定位到决定性一行：
```
⏭️ market_fund_flow_data.json → data/MARKET_FUND_FLOW_DATA.js | 纯盘后产物，非 post_close 构建跳过（防回滚）
```

**根因链**：
1. `v8_cn_fetch_cloud.yml` step20 调用 `python update_v8.py`（**无 --category 参数**，全量模式 category=None）
2. `update_v8.py` 里 2026-09-10 新增的防回滚护栏 `_should_skip...` 规定：
   `_file_category` 仅含 post_close 的「纯盘后产物」（如 market_fund_flow_data.json → MARKET_FUND_FLOW_DATA.js，共计数十项），
   **只在 `category == "post_close"` 显式授权时才重建**，否则跳过（防 13:48「旧 raw 洗新 data」回滚事故）
3. 无参数全量 build 的 category=None ≠ "post_close" → 纯盘后产物 **100% 被跳过**
4. 抓取侧（step8 selective）把 market_fund_flow_data.json 刷新成 15:22:49，但 build 侧永远不重建 JS → 错位

**影响面**：日志里一长串 SKIP（AI_INSIGHTS_COMPARE / ALGO_TRACK / BACKTEST_* / CANDIDATE / CRDS_CARD_DATA / EXPERIMENT / FACTOR_AUDIT / MARKET_FUND_FLOW_DATA / MARKET_ALERTS / CRISIS_DATA 等数十项纯盘后产物），全部停在各自上一轮重建时间。收盘相关的「市场资金流向」最直观。

**对照**：`v8_build_deploy.yml:145` 的 update_v8 调用**显式传了 `--category post_close`**（schedule 分支），所以部署流程能重建纯盘后产物；但日常的 v8_cn_fetch_cloud 抓取档缺这个参数 → 平时不报错、只是静默不更新。

## 三、修复（已推 main，commit 6e8baecc9）

```bash
CAT="${{ steps.cat.outputs.category }}"
if [ -z "$CAT" ]; then CAT="post_close"; fi
if [ "$CAT" = "all" ]; then
  python update_v8.py            # 覆盖 premarket/intraday
  python update_v8.py --category post_close   # 补齐纯盘后产物
else
  python update_v8.py --category "$CAT"
fi
```
