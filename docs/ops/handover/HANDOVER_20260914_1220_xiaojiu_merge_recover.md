## 三、🔴 给阿狸咪的硬提示（本次事故的方法论）

1. **推送前必须 `git fetch --force origin main:refs/remotes/origin/main`，并确认自己的基线含对方最新提交。**
   本次事故就是「本地工作树停留在旧版」直接推造成的。
2. **`git cat-file` 取基线后必须校验字节数 + 特征串**：
   本仓 `index.html` 完整版在 **110 万字节级别**；见 **90 万级别即为残缺**，立即中止。
   （11:46 我正因并发 `cat-file` 拿到 935160 字节残缺版而触发第一次事故。）
3. **禁止并发执行多个 git 命令**（尤其 `cat-file` 与 `fetch`/`push` 混跑）。
4. **推送后做双向校验**：「新写法在位 N/N」+「旧写法清零 M/M」。只看 md5 会被 CI 缓存戳干扰。
5. ⚠️ **CI 每次 build 都会改 `index.html`**（注入 `var BUILD` + 约 37 处 `?v=` 缓存戳）
   ⇒ **推后 md5 变了 ≠ 改动丢失**。判据 = 用 diff 过滤掉这两类，剩余差异须 100% 是本批改动。
