## 三、🔴 推送过程中的两次「防覆盖护栏生效」实录（沉淀技法）

本仓 tip 为**分钟级 churn**（CI bot 持续推 `raw_data/*.json` 与 `?v=` 缓存戳对齐）。
本次推送**两次被正确中止**，均非故障而是护栏按设计工作：

| 次序 | 现象 | 处置 |
|---|---|---|
| 第 1 次 | PATCH 前发现 tip `301b30ac` → `13eff111`（CI 推 `data/*.js` + `index.html`） | 中止（`force:False`），**不 force** |
| 第 2 次 | 重基线重放后 PATCH 前，tip 又 `13eff111` → `494b66cf`（CI 推 `raw_data/risk_gauge.json`） | 再次中止 |

**漂移性质甄别（关键）**：第 2 次漂移经 `GET /compare/<old>...<new>` 确认
**只改了 `raw_data/risk_gauge.json`，`index.html` 未变**（sha 仍 `015a208d0616`，
与我方基线**逐字节相同**）⇒ 属「**无关文件漂移**」，我方的 `index.html` 修改可安全叠加。

**最终采用的推送方式（建议后续沿用）**：
**单文件 Contents API 串行推送**（`PUT /contents/<path>` 带该文件自身 `sha`），
而非 tree+commit 方案。理由：
- tree+commit 要求**整棵树基线对齐** ⇒ 被无关文件的新提交顶掉（实测 2 次）
- Contents API 只要求**该文件自身 sha 匹配** ⇒ 不受他人改其他文件影响，更稳、更原子

**安全护栏（本次实装，逐条自证）**：
1. PUT 前重取该文件 `sha` + 逐字节比对基线，不匹配即 `sys.exit(2)`，**绝不 force**
2. PUT 后回读逐字节核验（两文件均 `一致=True`）
3. 两文件串行，前一个成功才推后一个

**缓存戳保全（易踩坑）**：`index.html` 的 `?v=` 是 CI bot 定期 bump 的缓存戳。
若用「我方基线整文件直推」会把旧戳**回退**，致全站 `data/*.js` 缓存失效。
本次在**远端最新真身**上重放补丁，实测：
- 推送前远端戳 `1789937407`（108 处）
- 推送时我方保留该戳（旧戳 `1789933508` count=**0**，未回退）
- 推送后 CI bot 正常 bump 至 `1789938234`（**不是清空**，`?v=` 共 112 次）
- `BUILD` 短 SHA 由 CI 注入为 `fe0cb9912`
