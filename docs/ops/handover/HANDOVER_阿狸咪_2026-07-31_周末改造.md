### P0：确认 `v8_sync_v6_data.yml` 在 cn runner 能正常读取 v6 数据

- cn runner 必须能访问 `E:\workspace\stock-scanner\data`（如路径不同，修改 `sync_v6_to_v8.py` 顶部 `V6_ROOT`）。
- 若 runner 与 v6 不同机：请在 v6 机器上建一个等效调度（调用 `sync_v6_to_v8.py --push`），或把 v6 数据同步到 runner 可见路径。
- **不要** 把 `sync_v6_to_v8.py` 放美国 runner 上跑（读不到 v6 数据）。

### P1：确认 v6 日常跑批时间

- `v8_sync_v6_data.yml` 16:45 同步 post_close 数据。请确保 v6 的收盘/算法脚本在 16:45 前已生成最新 `data/*.json`。
- 若 v6 收盘数据生成晚于 16:45，请把 `v8_sync_v6_data.yml` 的盘后 cron 往后调（如 17:10，在 17:00 build 之后；则下次 build 在次日 17:00 之前不会触发，需靠 raw_data push 触发）。
- 更稳的方案：在 v6 收盘链路末尾直接调用 `sync_v6_to_v8.py --category post_close --push`，而非等定时任务。

### P2：SH_SZ_HISTORY 硬编码内联

`index.html` 第 412 行左右硬编码了 `window.SH_SZ_HISTORY`（数据到 2026-06）。
- 方案 A：出生产者（历史成交额），写入 `data/SH_SZ_HISTORY.js`。
- 方案 B：删除该卡片（若不再需要）。
- **不要长期留硬编码旧数据**。

### P3：给 5 个无时间戳模块加时间戳

`guard_v8_freshness.py` 报无时间戳：`COCKPIT_ADVICE` `COCKPIT_TIER_RECOMMEND` `MAHORO` `STOCK_LIST` `TRIPLE_HISTORY`。请在 v6 对应生产脚本里写 `update_time` 或 `calc_time`。
