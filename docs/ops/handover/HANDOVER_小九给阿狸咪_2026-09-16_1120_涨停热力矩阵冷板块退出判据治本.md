## 三、根因（两条，缺一不可）

### 根因 A：判据是「全 0 才退」，等价于永不退

`fetch_limit_up_heatmap_v8.py` 旧判据：

```python
all_sec = {x for x in all_sec if not (
    all(v == 0 for v in [ ...近30日全部历史值... ])   # ← 30日全 0
    and sum(sector_counts.get(x, {}).values()) == 0    # ← 且今日仍 0
)}
```

判据要求**近 30 日每一天都是 0** 才剔除。实测：券商 30 日合计 46、固态电池 3 —— 只要历史上**有过任何一天非 0**，就**永久豁免**。

> 判据仿真复核：按旧判据，当前 15 个板块中**退出 0 个**——一个都不会退，完美印证根因。

### 根因 B：`fixed_sectors` 保底身份「完全豁免」退出闸门 + 永远排最前

```python
fixed_sectors = ["其他","半导体","军工","消费电子","通信设备","AI算力","医药",
                 "电力","地产链","白酒消费","券商","机器人","新能源车"]
sorted_sec = sorted(all_sec,
    key=lambda x: (0 if x in fixed_sectors else 1, ...),  # ← 保底永远排最前

```

「券商」在保底名单里 ⇒ ① 即便判据改对，`sorted_sec` 的排序键也让它永远靠前；② 占掉 `[:15]` 名额，把真正有热度的新板块（如光伏）挤掉。

## 四、修复（新判据）

```python
HEAT_MIN = 2          # 冷掉阈值：近 N 日合计 <= 此值 ⇒ 退出
STALE_WINDOW = 5      # 观察窗：最近 N 个交易日

_hist = {}
for s0 in existing.get("sectors", []):
    _hist[s0["name"]] = s0.get("data") or []
all_sec = set(fixed_sectors) | set(_hist.keys()) | set(sector_counts.keys())

def _recent_sum(name):
    """该板块最近 STALE_WINDOW 个交易日的涨停家数合计（含今日）。"""
    arr = list(_hist.get(name) or [])
    return sum(arr[-STALE_WINDOW:])

_dropped = sorted([x for x in all_sec if _recent_sum(x) <= HEAT_MIN],
                  key=lambda x: _recent_sum(x))
if _dropped:
    print(f"  🧹 退出冷板块（近{STALE_WINDOW}日合计 <={HEAT_MIN}）："
          + "、".join(f"{x}({_recent_sum(x)})" for x in _dropped))
all_sec = {x for x in all_sec if _recent_sum(x) > HEAT_MIN}
```

**关键设计决定**：
1. **为什么 5 日 / 2 家**：实测卡点刚好 —— 券商(1)/固态电池(0) 退出；地产链(5)/光伏(7) 保留。**零误杀**。
2. **为什么保底板块也要退出**：保底的语义是「**有热度时优先展示**」，不是「没热度也占位」。故保底**只保留排序优先权**，不再豁免退出闸门。
3. **数据来源**：全部读 `existing` 的历史列（已含今日写入的值），不额外依赖今日 `sector_counts`。

**⚠️ 本文件有**两处**相同代码**（增量路径 + 兜底路径），**两处必须同口径**。本次已同步改，勿只改一处。
