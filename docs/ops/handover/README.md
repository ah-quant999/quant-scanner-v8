## 二、命名规范：**时间优先**

```
YYYY-MM-DD_HHmm[_URGENT]_<发件>给<收件>_<主题>.md
```

**实例**

```
2026-09-10_2130_URGENT_阿狸咪给小九_派发源精简与假成功根治.md
2026-09-10_2200_阿狸咪给小九_补充审计+清理+三处缓存戳互踩.md
2026-09-11_0900_小九给阿狸咪_收盘数据核验回执.md
```

**规则**

| 段 | 取值 | 说明 |
|---|---|---|
| `YYYY-MM-DD` | 签发日期（北京时间） | 必须 |
| `HHmm` | 签发时刻，24 小时制、分钟级 | 必须。**读不到真实时间就写 `0000`，不许猜** |
| `URGENT` | 紧急件标记（可省） | 放在时间后，仍可按时间排序，又能一眼识别 |
| `<发件>给<收件>` | `阿狸咪给小九` / `小九给阿狸咪` | 双机双向 |
| `<主题>` | 简明中文 | 不要含 `?` `*` `:` `/`（Windows 非法字符） |

## 三、为什么按文件名排序，而不是按修改时间

- **`ls` 默认排序 = 文件名排序 = 时间排序**，无需任何额外操作。
- **绝不能用 mtime**：本仓库被坚果云实时同步，同步会**重写 mtime** →
  历史上读取器按 mtime 取"最新交接"取错过，这才是真正的隐患（读取器已改）。
- 每台机器有**两个专家会话并发**处理不同事务，签发时刻带分钟就足以区分
  「谁在什么时间做了什么」，时间差本身就是判别依据。

## 五、新建交接的正确姿势

```bash
python docs/ops/scripts/new_handover.py --from 阿狸咪 --to 小九 --topic "主题" [--urgent]
```

返回的路径直接 `git add` 即可。
