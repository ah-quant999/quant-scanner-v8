## 二、根因（双重）

### 根因① 前端判据 bug（致命 · 本次元凶）

`index.html` `renderAiSummary` 内陈旧守卫 **L2113**（旧版）：

```js
if(!d || !d.gen_time || isStale){
  contentEl.innerHTML='<div class="ipo-empty">AI市场速览数据暂不可用</div>';
  return;                      // ← 整卡清空 + 提前返回
}
```

`isStale` 判定（旧版 L2107）：

```js
if(!isSameDay && !isWeekend && minutes >= 540){ isStale=true; }   // 540 = 09:00
```

**缺陷**：把「**数据不是今天产的**」等同于「**没有数据**」。

本卡 `intraday` 档在 **09:00–09:25 之间必然还没产出**（盘前 08:25 cron 只跑 `premarket` 档，`intraday` 首班等本机调度器派发），而守卫恰在 **09:00 开闸**：

> **每交易日 09:00 到首班盘中刷新之间，卡片 100% 空白。**

今日实证：`AI_MARKET_BRIEF` 停在 `09-15 19:31`（收盘档），09:00 一到即被清空；10:03 数据刷新后才恢复。

### 根因② 数据侧（触发根因①）

今日盘中刷新批次未按时产出：
- `v8_cn_fetch_cloud.yml`：今日仅 08:16 盘前一班 + 09:49/09:51 两班长时间排队
- `v8_cn_fetch_intraday_lemoncat.yml`（盘中 20 分钟调度器）：今日 0 班，最近一班为昨晚 20:28

⇒ 数据停在昨日 19:31，正好踩中根因①的开闸条件。

### 附带缺陷③（跨周末漏豁免）

`isWeekend` 用 `mm`（=**今天**）算 `dayOfWeek`，而非判「今天是否紧接在非交易日之后」：

```js
var isWeekend = (dayOfWeek === 0 || dayOfWeek === 6);   // 旧：漏了周一
```

⇒ 周五数据在**周一 09:00 后**必被清空（周末豁免对周一无效）。

## 三、修法（三档处置 · 信息不丢失）

```js
// ① 真·无数据 ⇒ 保留空态（罕见）
if(!d || !d.gen_time){
  contentEl.innerHTML='<div class="ipo-empty">AI市场速览数据暂不可用</div>';
  if(timeEl) timeEl.innerHTML = '<span style="font-size:11px;color:var(--dim)">—</span>';
  return;
}
// ② 陈旧 ⇒ **不再 return**，改为顶部黄条（下方 var h=_staleBanner 拼首位）
var _staleBanner = isStale ? '<div ...>⚠️ 上一交易日数据 + 数据时间 + 正在等盘中首班刷新 …</div>' : '';
```

```js
// ③ isWeekend 补周一
var isWeekend = (dayOfWeek === 0 || dayOfWeek === 6 || dayOfWeek === 1);
```

**为什么不直接删掉守卫**：陈旧是真实状态、主人需要知道；但呈现方式应是**在内容之上加一句说明**，而不是把内容整卡抹掉。
