# v8 模块更新时段分类（盘前 / 盘中 / 盘后）

> 创建于 2026-08-13，基于实际 workflow cron + CATEGORY_MAP + 前端 tab 对应关系核验。
> **用途**：排查"某模块为什么没更新"时，先查该模块属于哪一档、对应哪个 workflow、哪个 cron。

## 三档定义

| 档位 | 触发时机 | 频率 | 典型 cron |
|---|---|---|---|
| **盘前（premarket）** | 每日 08:25（盘前一次性） | 每日 1 次 | `25 0 * * 1-5` (UTC+8) |
| **盘中（intraday）** | 09:00–16:30 每 30 分钟 | ~15 次/天 | `*/30 1-8 * * 1-5` |
| **盘后（post_close）** | 17:20 / 18:30（收盘后） | 每日 1–2 次 | `20 9 * * 1-5` / `30 10 * * 1-5` |

## Workflow 总览

| Workflow | 职责 | 触发 |
|---|---|---|
| `v8_cn_fetch_cloud` | 抓取全量外部数据（盘前+盘中+盘后） | Cron 08:25 / */30 09:00-16:30 / 17:20 / **21:30** 全量兜底 |
| `v8_algo_cloud` | 算法回测/候选池/龙虎榜等计算 | Cron 17:20 / 18:30 |
| `v8_build_deploy` | 构建 data/*.js + 刷 ?v= 时间戳 + 推 main | 由 algo_cloud 触发 / 手动 dispatch |
| `v8_health_patrol` | 每小时巡检，发现过期数据自动重派 | Cron 08:08–21:08 每小时 |
| `v8_daily_audit` | 每日审计（覆盖率/空值/延迟） | Cron 21:30 |
| `v8_backup` | 自动备份 | Cron 23:00 |
| `v8_ops_self_heal` | 自愈（重启失败 workflow 等） | 由 health_patrol 触发 |

## 排查速查

**"某模块数据停在 XX 点没更新"** 排查步骤：

1. 查上表确认模块属于哪一档
2. 对应 workflow 最近一次 run 是否成功（Actions 页）
3. 若盘前/盘后批次失败 → 检查 `v8_health_patrol` 是否已自动重派
4. 若盘中批次连续停更 > 2 小时 → 检查 cn runner 是否在线（`lemoncat-cn` / `alimi-cn`）
5. 若 runner 掉线 → 检查对应机器是否关机/断网，另一台应自动接手

## 关键约定

- **盘中只有「实时数据」和「板块」两个 tab 会持续刷新**，其余所有模块都是每日 1–2 次快照
- **盘前数据不会盘中更新**（日历/判定/停牌等是隔夜语境）
- **双机备份**：`lemoncat-cn`（小九）+ `alimi-cn`（阿狸咪），任一掉线另一台自动接手，无冲突风险（job 原子分配）
- **ubuntu-latest 兜底**：若两台 cn runner 都离线，workflow fallback 到 GitHub 托管 runner（美国 IP，中国源可能抓取失败）
