## 3. 取数与口径（核心论证）

### 3.1 为什么放弃 K 线路径

上件 §1 曾把「新浪美股日 K」列为唯一可用历史源。实施时实测**两条通路都不可用**：

| 通路 | 实测 | 判定 |
|------|------|------|
| 东财 `push2delay` `kline/get` | 返回空 `klines` | ❌ 弃 |
| 新浪 `US_MinKService.getDailyK` | 端点须 jsonp 形式才通；**末根恒滞后一天**（09-19 抓取时末根仍停在 09-17） | ❌ 弃（降为对照） |

⇒ 改为**直接取东财 `clist` 的动量字段**：不需要 K 线、不需要逐只请求、与报价同日同源。

### 3.2 动量字段逐位实测锁定

对全榜点名字段 `f3/f127/f109/f160/f110/f24`，用三只标的的独立自算值逐位比对：

| 字段 | 语义 | 验证 |
|---|---|---|
| `f3` | 当日涨跌幅% | AAPL −0.26 自算 ✅ |
| `f127` | 3 日% | NVDA 4.76 ✅ |
| **`f109`** | **5 日%** | AAPL **1.16** / NVDA **1.82** / BABA **3.60** 逐位精确 ✅✅✅ |
| `f160` | 10 日% | AAPL 2.41 / BABA 1.28 ✅✅ |
| **`f110`** | **20 日%** | AAPL **7.98** / BABA **−13.25** 逐位精确 ✅✅ |
| `f24` | 60 日% | BABA 13.47 ✅ |
| `f124` | 该行最后更新时间戳 | 用于取隔夜交易日 |

**收益**：一次 HTTP 拿全榜 + 全动量，比「全市场扫描 + 逐只 K 线」更快、更准、更省抓取预算。

**接线（零 workflow 依赖）**：`soft_10` 用 `git status --porcelain raw_data/ data/` 自动收集本次变更并推送
⇒ 新产物**自动上线**，不需要改任何 `.yml`（这点很关键：细粒度 PAT 无 workflow scope，改 yml 必 403）。

**为什么单挂 `premarket` 而不挂 `intraday`**：08:25 抓取时美东上一交易日已收盘，
报价接口给出的「最新价」**即上一交易日收盘价**，与「隔夜」语义天然对齐；
盘中抓到的仍是**同一根**隔夜数据，挂了只会白耗抓取预算。
