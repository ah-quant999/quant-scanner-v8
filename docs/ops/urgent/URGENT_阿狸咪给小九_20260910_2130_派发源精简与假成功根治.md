## 2. 🔴 新的派发源铁律（小九必须遵守：**不要再新增任何派发者**）

现场只剩「**一条主线 + 一个兜底**」，其余一律不得自行派发：

| 角色 | workflow | 触发 | 什么时候派 |
|---|---|---|---|
| **盘中唯一派发主线** | `v8_cn_fetch_intraday_lemoncat.yml` | GitHub cron 14 档（:00/:20/:40，跳午休） | 三重守卫放行即派 |
| **唯一状态型兜底** | `v8_cn_fetch_watchdog.yml` | cron :07/:22/:37/:52 | 数据陈旧 **>45min**（盘中）才动手 |
| **主体定时** | `v8_cn_fetch_cloud.yml` 自身 3 条 cron | 08:25 / 17:20-19:20 / 周末 09:00 | 盘前盘后周度 |
| 被派发主体 | `v8_cn_fetch_cloud.yml` + `_selfhosted` + `_hosted` | 上述三者 dispatch | 三者**共用** `v8-cn-fetch-cloud` 并发组 |

**为什么不能再加派发者（今日实证，47 个 run / 25 个 cancelled）**
GitHub 对同一 concurrency group **只保留 1 running + 1 pending**；第 3 个派发会把上一个 pending **顶掉 → cancelled**（多数 cancelled 的 run **连 job 都没生成**）。
今日 `v8_cn_fetch_cloud` 共 47 run：`success 22` / `cancelled 25`，且双 actor 多次同分钟互顶（13:10:04 两条、12:32 两条、16:10 与 16:17…）。两个 actor：
- `github-actions[bot]` = 云端调度器/守门
- `ah-quant999` = **阿狸咪本机自动化**，今日在 **08:16–18:02 小九白天时段密集派发**（违反双机分时铁律，已据此暂停 `27b5306c`）

**要补缺口怎么办**：改上面三个之一（调阈值 / 调守卫），**禁止新开 workflow 当第四个派发者**。新增 workflow 若带 cron，必须**双登记**（`align_logic_ops.py` 的 `MUST_HAVE_CRON` + `index.html` 运维段），否则 Pre-deploy audit 失败 → **全链阻断部署**。

## 3. 「假成功」的新判定：`landcheck`（小九必须理解，别误判为随机变红）

**病灶**：`v8_cn_fetch_cloud.yml` 有 **16 个消费步 `continue-on-error: true`**（2026-08-18 软失败策略）。失败只打 `::error::` annotation，**job 结论仍是 success** → run 全绿。于是看门狗/巡检/人眼看到 success 就认为"数据已刷新"，不再兜底 → 数据持续陈旧（今日盘中 26~102 分钟空窗的成因之一）。

**新逻辑**（`v8_cn_fetch_cloud.yml` 最末 step，`if: always() && steps.gate.outputs.skip != 'true'`）：
1. 不看"步骤有没有报错"，只看**结果事实**：用 Contents API（`Accept: raw` 直取 git blob，**不走 Pages CDN**，CDN 缓存会误判）读远端 main 上该 category 的代表文件；
2. 比对文件内 `update_time` 是否 ≥ `run_started_at − 3min`（容差）；
3. 分级：
   - **0 个推进** = 整轮空转的假成功 → `::error title=v8-fake-success` + **`exit 1`（run 如实变红）**
   - **部分推进** = 局部软失败 → 由既有 `softfail-summary` 覆盖，**本步不重复报红**（避免噪音）
   - 全解析不出 = 证据不足 → **不报红**（宁可不报，不误报）

**⚠️ 三条必须记住的**：
- **cloud run 变红 ≠ 部署失败**：`v8_build_deploy` 用 `workflow_run: types:[completed]`（**不筛结论**）+ push 触发，实测不阻断。看到红先看是不是 `v8-fake-success`。
- **PROBE 清单必须与 `v8_cn_fetch_watchdog.yml` 的 PROBE 同源同口径**（单一事实来源）。改一处必须改两处。
- `landcheck` 与看门狗**分工不重复**：landcheck 抓「本轮整轮空转」，看门狗抓「跨轮局部文件陈旧」。
