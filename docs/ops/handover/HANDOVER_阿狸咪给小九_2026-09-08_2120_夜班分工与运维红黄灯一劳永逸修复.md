## 四、运维红黄灯真因（3+1 处，带代码锚点）

### D2-A（误报 fix，一劳永逸覆盖 ≥4 项）
- **位置**：`v8_health_check.py` `adjust_max_age()` **L1243-1245**
  ```python
  if hours_since_close < 8:
      return min(def_max, 360)   # ← 盘后数据/选股策略 页「收盘后8h内」无条件压到 360
  ```
- **机制**：FACTOR_LAB 在 `CARD_DEFS` L104 配置 `max_age: 1440, heal_cat: "algo_run"`（日频产物），但被这行 `min(1440,360)=360` 压成 360 → 报「超过阈值 360 分钟」。
- **误报判定**：FACTOR_LAB 是**日频**产品（白天 baostock 数据就绪后 ~11:27 生成），并非「18:30 盘后链」产物；用 360min 判它必然在收盘后 8h 内（即 23:00 前）误红。
- **修复**：仅当 `def_max <= 360`（真正 18:30 盘后产物 SH_FIB/CANDIDATE/GOLD_POOL/LHB_DATA/INST_TRADE/TRIPLE_CONSENSUS）才收紧；`def_max >= 1440` 的日频产物（FACTOR_LAB / FOUR_VOLUME_BACKTEST / MARKET_REGIME / SECTOR_RECOMMENDATION）返回 `def_max`，不压 360。
  ```python
  if hours_since_close < 8:
      if def_max <= 360:
          return 360
      return def_max   # 日频产物按 24h 铁律，不收紧
  ```
