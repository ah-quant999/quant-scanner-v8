## 11. 本轮新增判据

- **78**：本仓 **`.git/shallow`（27 条）** ⇒ `git merge-base --is-ancestor <x> <tip>` 对落在 graft 边界之外的提交**必然假阴性**，`git log --stat <边界提交>` 会把全仓文件显示为「新增」、`%p` 显示为空。**严禁**用这两条判「提交是否在 main / 是否被覆盖」；替代 = ① `git cat-file -p <c> | head -3` 看有无 `parent` 行（区分真根提交 vs 浅边界）② **内容面 blob 匹配** `git rev-parse <tip>:<path>` ③ GitHub commits API。
- **79**：交接档「提交」列必须写**线上落地 SHA**（`ls-remote`/API 返回）。API 推送产生的 commit 与本机 `git commit` 是**两个不同对象** ⇒ 写本机 SHA 时对方**无法核验**（本轮实例：内容 4 blob 全中，但本机 `d47cb3689` 不可核验）。建议档头写「线上 tip SHA」并在正文附「本机提交 SHA（仅供参考）」。
- **80**：**「桥接产物 = 源 raw 的无条件投影」** ⇒ 判某卡会不会回退，必须同时查三件事：① 桥接有无**单调不回退**守卫 ② 有无**纯盘后防回滚**跳过（`_pure_pc`）③ 源 raw 是否在**写者白名单**。三者齐缺 ⇒ 回退面成立；本轮实测「②命中」⇒ 轻量档/本机全量档**安全**，仅 `--category post_close` 路径暴露。
- **81**：给出「缺某权限/缺某配置」类处方前，先**静态复核目标文件是否已含该权限/该 env**（本轮 D4：`actions: write` 与 `V8_GITHUB_TOKEN` 均已在位 ⇒ 处方作废，真因在 PAT 生效面）。
