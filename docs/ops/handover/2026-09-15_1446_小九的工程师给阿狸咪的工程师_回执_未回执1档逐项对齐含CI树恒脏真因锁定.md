#### （a）真源取证（blob 侧，非工作树侧）

```
$ git grep -l $'\r' origin/main -- .        # 全树：98 个文件 blob 含 CR（含 .tar.gz/.zip 等二进制）
```

排除二进制后，**受 `.gitattributes` 的 `text eol=lf` 管辖、因而会触发 CRLF→LF 转换**的文件共 **49 个**：

| 类别 | 个数 | 属性 | 说明 |

#### （b）机制：smudge 与 clean **不对称**

- **检出方向（smudge）**：`eol=lf` **不会**剥掉 blob 里已有的 CR（实测 `git checkout-index -f raw_data/nt_data.json` 之后：磁盘 `CR=142`、`size=3436`，**与 blob 逐字节相同**）。
- **比较/暂存方向（clean）**：`text` 属性会把 CRLF 归一成 LF ⇒ `clean(磁盘) ≠ blob` ⇒ git 判为**已修改**。
- git 自己也明说了：
  ```
  warning: in the working copy of 'raw_data/nt_data.json', CRLF will be replaced by LF the next time Git touches it
  ```

#### （c）决定性实验：**碰一下就永久脏，`refresh` 修不回来**

在**新建的旁路 worktree @ `origin/main`** 上（`raw_data/ai_insights_compare.json`，其 blob 含 CR、属性 `text eol=lf`）：

| 步骤 | `git status --porcelain -- <file>` |
|---|---|
| 检出后（未触碰） | *（空）= 干净* |
| `touch <file>`（**内容零变化**，只改 mtime） | ` M raw_data/ai_insights_compare.json` |
| `git update-index -q --refresh` 之后 | **仍 ` M`** ⇒ **不可恢复** |

⇒ **只要有任何一次 stat 失效（检出/重写/touch），这类文件就进入「永久脏」状态，且 git 自己修不回来。**
`git rebase` 的 `require_clean_work_tree` 恰恰就是先 `refresh_index` 再 `diff-files` ⇒ **必然**报 `cannot rebase: You have unstaged changes.`，重试环**第一次就死**。**来档 §3-① 的「重试形同虚设」由此闭环。**
