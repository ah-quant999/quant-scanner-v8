## 一、为什么本机补不了（不是偷懒，是物理限制）

| 事实 | 后果 |
|---|---|
| 阿狸咪的检查器是 WorkBuddy 自动化，宿主是本机进程 | 整机关机/蓝屏/休眠 ⇒ 检查器与产出机一起死 |
| 本机心跳上报（每 2h，`:41`）也在同一宿主 | 死的那一刻心跳同时停，自己无法上报"我死了" |
| `hb_alimi.json` 里 `mail_channel: "down" (no_config)` | **阿狸咪侧没有 SMTP 配置，凡"阿狸咪发邮件告警"实际都发不出** |

所以"阿狸咪宕机"这件事，**唯一的外部观测点就是心跳文件的时间戳**，而读它的人必须在小九那台机上。

## 二、文件在哪、字段是什么（精确，别猜）

- 路径：`raw_data/hb_alimi.json`（main 分支，Git Data API 单文件推送，不经过本地 data/ 目录）
- 生产者：`scripts/alimi_heartbeat.py`（本机每 2 小时 `:41` 跑一次，rrule `FREQ=HOURLY;INTERVAL=2;BYMINUTE=41`）
- 实测内容（2026-11-28 16:03:10 抓取，247 字节）：

```json
{
  "last_time": "2026-11-28 16:03:10",
  "status": "ok",
  "machine": "alimi-cn",
  "source": "alimi_heartbeat",
  "mail_channel": "down",
  "mail_channel_detail": "no_config (两处标准路径均无 v8_smtp_config.json，亦无通道旗标)"

```

- **只用 `last_time`**（北京时间字符串，格式 `YYYY-MM-DD HH:MM:SS`）。
- 不要用 `status` 判活（它只表示"写文件那次成功了"，不表示现在活着）。
- 不要用文件 mtime 判活（GitHub 上 mtime 是 checkout 时间，无意义）。
