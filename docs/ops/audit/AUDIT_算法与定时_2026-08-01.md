## 二、定时任务时序测算（你的核心关切）

### 2.1 铁证：龙虎榜 17 点跑必然拿隔夜数据 → 算法损失
- `fetch_lhb.py` 取数逻辑：`if now.hour < 17: 取昨天，否则取今天`。
- 但**交易所龙虎榜 17 点后才发布**（v6 代码原注释白纸黑字："龙虎榜17点后出"）。
- 17:00 整点跑 → 查"今天"的龙虎榜 → 东财返回空 → `main` 直接 return **不写文件** → `lhb_result.json` 静默保留昨天数据。
- **受害算法**：三重共识、机构游资共振、top10 的龙虎榜维度全部用隔夜龙虎榜。
- **v6 成熟系统的做法**（我们迁移时丢了）：
  - `close_p1` **17:30** — 全量数据抓取（研报/行情，**龙虎榜除外**）
  - `close_p2` **18:30** — **龙虎榜（已出）** + scanner 全量 + 各类生成
  - `close_deploy` **19:30** — 最终部署

### 2.2 已修复的时序问题
| 项 | 原状 | 已改为 | 原因 |
|---|---|---|---|
| `v8_algo_run.yml`（算法链） | 17:00 单跑 | **18:30 单跑** | 等龙虎榜发布，对齐 v6 close_p2 |
| `v8_build_deploy.yml`（构建部署） | 17:00 schedule + push 触发 | **仅 push 触发**（删 17:00 schedule） | 原 schedule 与算法链竞态，会先用旧 raw_data 部署一版陈旧数据；算法链 18:30 推送 raw_data 时会经 push 自动触发构建，schedule 纯冗余且有害 |

### 2.3 时长测算（够不够跑完+部署）
- **盘中抓取** `v8_cn_fetch`（08:25 / 10:30 / 11:30 / 13:05 / 14:00 / 15:05 / 15:30）：每次仅抓行情快照，秒级~1 分钟，间隔 30-90 分钟 → **绰绰有余**。
- **盘后算法链** `v8_algo_run`：17 个脚本按依赖顺序跑，重头在 baostock 回测 + mootdx/GTimg 候选池，估算 **15-25 分钟**；stage+push ~1 分钟；云端 build+deploy ~3-5 分钟。18:30 起跑 → **19:00 前全部完成部署**，距次日交易充裕。
- **结论**：时长从不是瓶颈，问题只在"起跑时点太早导致数据没齐"。

### 2.4 盘中密度（附带建议，非必须）
现盘中 5 个快照（10:30/11:30/13:05/14:00/15:05），14:00→15:05 有 65 分钟空档。对"盘中追热/ETF 三连板"这类实时卡，若要更贴近 30 分钟一档，可补 10:00 / 14:30 两点。属可选优化，不影响盘后主链。

## 四、算法"改进升级" · 决策记录（2026-08-01 用户拍板）

> 用户决策：**第 1-4 项「修复」；第 5 项（缠论买单独入 B 档）「不要」**。均已落地并通过全链验证（17/17 算法 0 失败）。

1. **回测幸存者偏差（P1）→ ✅ 已修**：`backtest_tdx.py` 回测宇宙=当前金股池 → 胜率高估。
   - 落地：新增「历史金股池快照并集」机制（编排器每日保存 `gold_pool_YYYYMMDD.json`），回测信号日取当日时点并集池，逐步消除幸存者偏差；同时 `win_rate` 改为 `win/(win+loss)`（排除平盘）。

2. **两个回测引擎"胜率"口径打架（P1）→ ✅ 已修**：统一为 `win/(win+loss)` 排除平盘（与 `backtest_comprehensive` 一致），站内两处"胜率"现已可比。

3. **top10 总分未归一（P1）→ ✅ 已修**：`total_score` 各分项相加（理论满分 250）被下游当百分制 70/80 阈值用。
   - 落地：`total_score` 归一化到 0~100（`min(100, round(raw/250*100))`），历史快照同步回刷。共识/重叠判定阈值语义已对齐。

4. **龙虎榜细节口径（P2）→ ✅ 已修**：`fetch_lhb.py`
   - `DETAIL_LIMIT` 死代码 → 改为按净买额排序截断前 N 只分析（防超时限流）；
   - 「未识别」席位不再并入「游资」→ 单列，避免污染机构-游资共振判定；
   - 节假日无数据 → 写 `trading:false` 占位，避免沿用陈旧数据。

5. **驾驶舱 B 档「缠论买单独」入档 → ❌ 用户否决**：维持现状（缠论买单独不入 B 档），选股范围不变。逻辑详解页已明确此口径。
