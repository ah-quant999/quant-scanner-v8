## 二、查出的真错 + 修法（`bfdf8c488`）

### 错在哪

```python
# 旧（错）
gap = (d - _last_trading_day(d)).days
if 0 < gap <= 3:                 # 距上个交易日 ≤3 天就算应跑日
    return d, "t1", ...
```

实测（联网取真实交易日历 8797 条，1990-12-19 ~ 2026-12-31）：

| 日期 | 星期 | 旧判据 | 应该是 | 性质 |
|---|---|---|---|---|
| 2026-09-25 | 五（中秋第 1 天） | t1 | t1 | ✅ |
| **2026-09-26** | 六（中秋第 2 天） | **t1** | none | 🔴 误跑 |
| **2026-10-02** | 五（国庆第 2 天） | **t1** | none | 🔴 误跑 |
| **2026-10-03** | 六（国庆第 3 天） | **t1** | none | 🔴 误跑 |
| 2026-10-05~10-07 | 一~三 | none | none | ✅（gap>3 才停） |

两条后果，都不是「少跑」而是「乱跑」：

1. **白跑整链**：算法链实测 84+ 分钟，国庆要白跑 2 轮；
2. **产物 `update_time` 被刷成非交易日日期**（如 `10-02`）⇒ 主站卡片会显示「10-02」这类
   **不存在的数据日** —— 这直接冲击主人「当天交易日可靠数据」的底线。

### 修法

判据改为「**连续休市段的第一天**」（前一天是交易日），主人三条规则**全部自动成立**：

| 日子 | 前一天 | 判定 | 结果 |
|---|---|---|---|
| 周六 | 周五（交易日） | 段首 | ✅ 跑 |
| 周日 | 周六（非交易日） | 非段首 | ✅ 不跑 |
| 假期第一日 | 交易日 | 段首 | ✅ 跑 |
| 假期第 2 日起 | 非交易日 | 非段首 | ✅ 不跑（**含假期里落到周六的那天**） |

配套改动（判据改「段首」后的必要适配）：`_backfill_candidate` 的 `lookback` **2 → 10**、
`decide(--force)` 与 `--recheck` 的 **3 → 10**。原因：回填必须能跨过**整段**连续休市
（最长 = 国庆 7 天 + 前后周末 ≈ 9~10 天）才能找到上一次应跑日；原 2 太短，国庆场景会
漏掉假期首日 `10-01`。
