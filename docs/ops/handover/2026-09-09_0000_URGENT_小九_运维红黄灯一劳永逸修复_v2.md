## D2-A：HEALTH_CHECK 误把日频盘后产物压成 360min（覆盖 ≥4 项）

**文件**：`v8_health_check.py`
**函数**：`adjust_max_age(def_max, page=None)` **L1243-1245**

```python
    if page in ("盘后数据", "选股策略"):
        close = last_trade_day_close(n)
        hours_since_close = (n - close).total_seconds() / 3600
        if hours_since_close < 8:
            return min(def_max, 360)   # ← 罪魁：def_max=1440 的日频产物也被压 360
        return int(hours_since_close * 60) + 180
```

**现象**：FACTOR_LAB（`CARD_DEFS` L104 `max_age:1440`）报「超过阈值 360 分钟」。

**修复**（仅收紧真正 18:30 盘后产物，日频产物不压）：

```python
        if hours_since_close < 8:
            if def_max <= 360:
                return 360          # 真正 18:30 盘后产物（SH_FIB/CANDIDATE/GOLD_POOL/LHB_DATA/INST_TRADE/TRIPLE_CONSENSUS）
            return def_max          # 日频产物（FACTOR_LAB/FOUR_VOLUME_BACKTEST/MARKET_REGIME/SECTOR_RECOMMENDATION）按 24h 铁律
```

**影响**：一次性根治所有 `def_max>=1440` 的盘后/选股日频产物误红，不止 FACTOR_LAB。

## D2-C：看板「已超更 75 分钟」假告警

**文件**：`index.html` **L9537-9543**（任务运行看板 `liveUpdated`）
**现状**：
```js
const liveUpdated = cands.length ? cands.sort().pop() : nowStr;
```
**机制**：`cands` 混算所有 `window.*` 时间，含 `window.HEALTH_CHECK.updated`（30min 节奏）→ 取陈旧 max 误报。
**修复**：
```js
const hcUpdated = window.HEALTH_CHECK && window.HEALTH_CHECK.updated;
const liveUpdated = hcUpdated || (cands.length ? cands.sort().pop() : nowStr);
```
并把同段 `isStale = staleMin > 30` 改为 `isStale = staleMin > 60`（与 30min 轮转+30min 缓冲对齐）。
