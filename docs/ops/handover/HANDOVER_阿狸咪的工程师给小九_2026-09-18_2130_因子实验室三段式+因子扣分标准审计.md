## 二、🔴 扣分标准审计（主人追问的直接答案）

### 2.1 实测总表：因子在历史产物里的真实痕迹

扫描 `raw_data/final_recommend.json` **29 轮真实产物 / 共 1333 条候选**（2026-08-27 ~ 09-18），
直接统计产物 `all_candidates[].signals`：

| 因子信号 | 累计出现 | 占比 | 是否计分 | 分值 |
|---|---|---|---|---|
| `放量弱势` | **0 次** | **0.0%** | 声称计分 | −0.5 |
| `缩量强势` | 410 次 | 30.8% | 不计分 | 0 |
| `高ROE` | 454 次 | 34.1% | 不计分 | 0 |
| `高手共振` | 37 次 | 2.8% | 不计分 | 0 |

⇒ **唯一声称计分的「放量弱势 −0.5」，29 轮从未生效一次。**

### 2.2 为什么从未生效：格式 bug（已修）

`algorithms/final_recommend.py` 原 `_weak` 集合：

```python
_weak = {norm_code(x.get("code")) for x in _at_bot if x.get("code")}
for key, r in pool.items():
    if key in _weak:                      # ← 恒为 False
        r["signals"].append("放量弱势")
```

`name_utils.norm_code()` 只去 `sh/sz/bj/hk` 前缀与下划线，**不剥点**：

| 表达式 | 值 |
|---|---|
| `norm_code("sh.600479")` | `".600479"`（**带点**） |
| `pool` 的 key = `norm_code(code).lstrip(".")` | `"600479"`（**无点**） |

⇒ `"600479" in {".600479", ...}` = **False** ⇒ 标签永不写入 ⇒ `weak_penalty` 永不执行。

⚠️ **同类坑本文件此前已犯过一次**（L706 注释原文：「`norm_code` 不剥点 → pool key 带点 →
画像/止损/行情 lookup 全失配」）—— 当时只修了 `ensure()` 侧，**漏修此处**。

**修法**（本件已推）：补 `.lstrip('.')`，与 pool key 同口径。

### 2.3 第二个问题：设计上不相交（修了 bug 也几乎不触发）

`bottom` 榜 = `abn` 最大的 10 只（**极端放量**、弱势特征）；
`top` 榜 = `abn` 最小的 30 只（**缩量**、强势特征）；
而候选池由选股策略产出，天然偏缩量强势 ⇒ **两集合语义相反**。

实测（`FACTOR_LAB.js` blob `378f45d098f2` × `final_recommend.json` blob `679906813b5c`）：

```
bottom ∩ pool = 0     ←「放量弱势」能触发的票数
bottom = ['000560','003040','300413','600127','600479','600613','600721','601086','601949','688356']
pool   = ['00291','01109','02318','06862','09866','09987','300124','300199','300390','300502','300857','301308', ...]
```

⇒ **即便格式 bug 修好，本条也几乎恒为 0 分。** 这是**设计层面**的空转，非数据问题。

### 2.4 第三个问题：没有回测依据

`−0.5` 的**唯一依据**是源码里的一行注释：

```python
# 方案B 放量弱势扣分：被异常换手率 bottom 命中的票，若同时被其他源选中则 −0.5
```

注释只说了「是什么」，**没说为什么是 0.5**（不是 0.1、不是 2.0）。对比同仓另一处因子计分：

| | `final_recommend.py` 的 `−0.5` | `generate_top10.py` 的 P5 `+6/+3` |
|---|---|---|
| 回测闸门 | ❌ 无 | ✅ `verdict=PASS` 才启用（`factor_walkforward.json`） |
| 最低证据门槛 | ❌ 无 | ✅ `P5_MIN_EDGE=0.30`（\|利差\| 低于此不启用） |
| 分层口径 | ❌ 无 | ✅ 池内分位前 20% / 20~40% |
| 量纲哨兵 | ❌ 无 | ✅ 池内中位成交额须落在 1 亿~200 亿 |
| 样本门槛 | ❌ 无 | ✅ `P5_MIN_POOL=20` |
| 实测成绩 | ❌ 无 | ✅ amt60 IR_OOS 0.877 / turntrend 0.872，7/8 年 Top 层胜率 >55% |
| 明文原则 | ❌ 违反 | ✅ L693「**只加分不扣分：反向档位在 walk-forward 里无显著负 edge，不给凭空的惩罚**」 |

⇒ `−0.5` 恰是 P5 明文禁止的「**凭空的惩罚**」。同仓两套标准打架。

### 2.5 第四个问题：注释与实现不一致（3 处）

| 因子 | 代码注释声称 | 实际对 `final_score` |
|---|---|---|
| `异常换手率` | 整源剔除 | 0（只写 `tags`）✅ 一致 |
| `ROE_TTM` | **降档加分 1.0/0.75/0.5** | **0** —— `sc = _roe_score(i)` 算完**从未写入任何计分字段**（算完即弃）❌ 不一致 |
| `高手跟踪` | 整源剔除 | 0（只写 `tags`）✅ 一致 |

⇒ 注释所称「ROE_TTM 降档加分」**从未生效过**。本件已删该两行与 `_roe_score()` 定义。

### 2.6 结论

**「因子扣分标准」= 三重空转：无依据 + 设计不相交 + 代码失配。**

⇒ **因子在本层的实际计分影响 = 0，现状等于「全部只做标注」。**

⇒ **处置原则（本件采用）**：**不改 `−0.5` 的数值**（改权重违反「绝不按短样本调权重」红线，
且 bottom 榜 vs top 榜谁负谁正尚无证据），改为 **可开关 + 如实公示 + 交主人裁决**：

| 开关 | 效果 |
|---|---|
| `V8_FACTOR_WEAK_PENALTY=1`（默认） | 维持 −0.5，产物标 `evidence="未回测"`，前端显 ⚠️ |
| `V8_FACTOR_WEAK_PENALTY=0` | 置 0（`signals` 照写、标签照展示，只是不减分） |

**待办**：把 `abnormal_turnover.bottom` 纳入 walk-forward 回测 ——
出显著负 edge ⇒ 保留并加权；否则按 P5 原则降为「仅标注」。
