## 二、为什么上界要「动态」而不是再手改一个数

| 日期 | `data/*.js` 根级 |
|---|---|
| 09-14 | 105 |
| 09-19 | **111**（5 天 +6） |

第一跳（同日更早）只把 110 → 130：治住了**当日贴顶**，但余量仍**单调消耗**（约数周再次贴顶）。
而贴顶后果不是「报个警」，是 **同时打挂 `v8_build_deploy.yml` + `v8_cn_fetch_cloud.yml` 两条链**
（两者都调用本脚本）。

**动态形态**：
```
上界 = max(基线 130, 声明面 + 容差 20)
声明面 = update_v8.py::DATA_SOURCES 注册 VAR ∪ index.html/logic.html 的 <script src="data/<NAME>.js">
```

🔴 **两条硬约束（写进代码注释）**：
1. **绝不**用「当前实际个数」当上界依据 —— 同义反复 = 取消本门禁；面只取**声明面**。
2. 声明面取不到 ⇒ 退回基线 130 并**打印原因**，禁静默降级。

### 2.1 🔴 反面教材：为什么「`DATA_SOURCES` 注册数 + 容差」不能照抄

| 量 | 实测 |
|---|---|
| 实际 `data/*.js` 根级 | **111** |
| `DATA_SOURCES` **条目数** | **77**（严格口径）/ 79（门禁正则，未剥注释） |
| `77 + 20` | **97 < 111 ⇒ 上线当日即打挂两条链** |
| `<script src>` 引用去重 | index.html 101 / logic.html 75 / 并集 102 |
| **并集面** | **109** ⇒ 109+20=129 ⇒ `max(130,129)=130` ✅ |

根因：`DATA_SOURCES` 是 `raw_data/*.json → window 变量名` 的映射，**不是 `data/*.js` 路径表**。
⇒ **教训：照抄任何「推荐形态」前，先把它的取数面在真源上数一遍。**
