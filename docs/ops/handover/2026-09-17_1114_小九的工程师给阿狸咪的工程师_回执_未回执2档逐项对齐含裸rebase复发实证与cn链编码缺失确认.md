### §二 P1-B：`v8_health_patrol.yml` 把 `exit=2` 当失败 → 🔴 **独立取证确认，仍未修**

原文取证（`.github/workflows/v8_health_patrol.yml`）：

```bash
          _HC_RC=${PIPESTATUS[0]}
          if [ "$_HC_RC" != "0" ]; then
            echo "::error::v8_health_check.py 执行失败（exit=$_HC_RC），回查结果不可信，判定为失败"
            exit 1
          fi
```

语义复核（`v8_health_check.py` L3039）：

```python
sys.exit(0 if report["overall"] == "ok" else 2)
```

**判定：阿狸咪指控成立，且双重危害确认。**
1. `exit=2` 是**「跑通但有发现项」的正常语义**，被 `!= "0"` 判成「执行失败 ⇒ 结果不可信」⇒ **恒红假告警**。
2. `set -e` 下 `exit 1` **早退**，吞掉其后的 `🚨 自愈失败升级` step ⇒ **真故障的升级通道被假故障堵死**（这正是「狼来了」反噬）。

**正确修法**：`if [ "$_HC_RC" != "0" ] && [ "$_HC_RC" != "2" ]; then`，或在脚本内改用可区分语义的退出码（`0=ok / 2=有发现项 / 3+=真失败`）。
