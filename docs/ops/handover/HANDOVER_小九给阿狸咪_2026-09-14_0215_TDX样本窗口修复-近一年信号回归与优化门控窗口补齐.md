## 二、根因链（三层，缺一层都解释不了现象）

### 层 1｜样本窗口被最长持有期吃掉（**真根因**）

`backtest_tdx.py` 原判据（第 575 行）：

```python
if idx is None or idx + max(HOLD_DAYS) >= n:   # max(HOLD_DAYS) 现为 250
    continue
```

要求**最长档 T+250** 有完整前瞻数据才记录该信号日。09-13 把持有阶梯从 5 档扩到
12 档（末档 250）后，**最近 250 个交易日的信号被整条跳过**——不是算出 0，是压根没算。

- 实测：产物信号窗口止于 **2025-09-01**，近一年样本凭空消失（短档 T+1/T+5 也白损失）。
- 而 `calc_forward_return()` 对 `target >= n` **本来就安全返回 None**，
  `_accumulate()` 也对 None **逐档跳过** ⇒ 那条 `max(HOLD_DAYS)` 护栏是**过度保守的纯累赘**。

### 层 2｜优化门控的 regime 序列窗口远短于信号窗口

`_fetch_index_ohlc(code, prefix, days=150)` —— 150 **自然日**，扣掉 regime 自身
21 日预热后只剩 **约 76 个交易日**（2026-05-28 起）。

层 1 让信号止于 2025-09-01 ⇒ **两个窗口交集恒为空** ⇒ `opt["total"] == 0`。

### 层 3｜0 样本时「静默丢字段」而非报错

```python
if opt_summary:
    if opt["total"] > 0:
        result_data["optimized_summary"] = sd     # ← 只有 >0 才写
```

0 样本时**整个 `optimized_summary` 字段不写**、无告警。下游：

```python
opt = bt.get("optimized_summary")
if not opt:
    sys.exit(1)          # ← E 批链一步失败；且 current_regime 永不刷新
```

> 前一批（09-14 01:10）裁剪掉 66 只旧口径僵尸条目前，这 66 只的信号延到
> 2026-07-07，**恰好覆盖了 regime 窗口** ⇒ 143 个匹配一直存在，缺陷被完全掩盖。
> 裁剪把掩盖物拿掉后立刻暴露：**143 → 0**。

## 六、给阿狸咪的三条硬提醒

1. **不要把 `backtest_tdx._merge_market_regime` 与 `regime_filter._merge_market_regime`「统一」**
   —— 两者**角色不同**：前者算**全历史 regime 序列**（供回测门控，窗口必须覆盖信号窗口），
   后者算**当前状态**（供 `final_recommend`/`generate_top10` 实时门控，只取近 150 天 + 有
   `stale_days` 失败语义）。函数体逐行相同，**窗口不同是刻意的**（已逐键比对
   `OPTIMIZED_REGIME_SIGNALS` 与 `OPTIMIZED["regime_signals"]`：完全一致）。
2. **凡往 `backtest_tdx.json` 顶层加字段，必须同步两处白名单**：
   `update_v8.py::_make_lite` **和** `split_inline_data.py::make_lite`（重复实现，已漂移过一次）。
3. **改样本集合/口径，一律只改 `ENTRY_CALIBER_VER` 一个数字**，断点续跑会据此把全部标的
   重算（本次即是：2 → 3 ⇒ 172 只全量重算）。别再另加开关。
