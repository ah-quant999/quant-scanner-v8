## 正文

### ① `api_push_raw.py` 唯一推送步并发化 + 总时长软闸 —— commit `15404ba6566f`

**症状**：run `#35847153922`（09-23 18:09 CST）step1–13 全 success（算法跑批✓ / 重生成 data\*.js✓ / 候选池行情✓），
**step14「唯一推送」failure** ⇒ step15 推 index.html / step16 机器校验 **双双 skipped** ⇒ 整拨 data/raw_data **零推送**。

**根因**（日志原文 + 源码实测）：
`The action '📤 唯一推送' has timed out after 20 minutes.` —— 卡满 job 级 `timeout-minutes: 20` 被硬杀，
tree/commit 从未创建。本步是**串行**推送：每文件 2 次网络往返（`GET contents?ref=` 防倒退比对 + `POST /git/blobs`），
变更面数十文件（raw_data 173 个 + data/\*.js）⇒ 总时长 O(n)、与跨境延迟相乘必然撞穿 20 分钟。
同段日志里候选池行情 6 个批次全 `RemoteDisconnected` ⇒ 同一时刻 runner 跨境网络劣化。
**为何 480s 心跳看门狗没拦住**：旧实现每个文件处理完都 `_beat()` ⇒「文件级有进展」永远成立
⇒ 看门狗只在**单文件**卡 >480s 时触发；本次是「总量问题」非「单点挂死」，故形同虚设。★教训

**修法**：
1. **并发化**：per-file（防倒退比对 + blob 上传）进 `ThreadPoolExecutor`（`PUSH_CONCURRENCY`，默认 6）；
   `tree` / `commit` / `PATCH ref` 仍**严格串行**（有前后依赖）。
2. **总时长软闸** `PUSH_SOFT_DEADLINE_SEC`（默认 720s）：超时停止收剩余文件、用**已完成部分**提交后 **exit 9**
   ⇒「部分落地 + 明确报失败」远优于「被硬杀 ⇒ 零落地 + 假绿」。
3. **线程安全**：`_push_one()` 只做 I/O 只返回结果，**绝不写共享状态**；累加全在主线程 `as_completed` 里（无需锁）；
   `_beat()` 也只在主线程 ⇒ 看门狗恢复应有作用。
4. 未动 workflow `timeout-minutes`（软闸 12min + commit 8min 裕量，少动一个风险点）。

**线上实证**（run `#35862602672`，head `c021f845` 已含本补丁）：
```

📊 并发推送收工：耗时 26s / 未变化 0 / 防倒退 0 / 待更新 22 / 失败 0
🚀 并发推送启动：42 个文件 / 并发 6 / 软闸 720s
📊 并发推送收工：耗时 16s / 未变化 17 / 防倒退 8 / 待更新 17 / 失败 0
✅ raw_data 已推送（第 2 次）commit b8c2e4da
```
**42 个文件 16 秒推完**；防倒退守卫照常工作（跳过 8 个陈旧文件）；中文无乱码。
⇒ cn fetch 的 soft_10/soft_14 推送步**同源受益**（同用本脚本）。

**回滚**：`PUSH_CONCURRENCY=1` 即退化为串行（行为等价改动前）；`PUSH_SOFT_DEADLINE_SEC` 可调大。

### ③ algo workflow step15「同步 ALGO_TRACK ?v」防崩 + 防残缺 + 软失败 —— commit `1c069110e274`

**症状**：run `#35862602672` step14 推送 **success**（数据已上线），但
**step15 failure** ⇒ **step16 机器校验被 skip**（真数据却整轮无校验）。

**根因**（源码实测）：step15 inline python 中
```python
for _att in range(1, 4):
    meta_sha, html = _fetch_main_html()   # ← 写在 try【之外】
    ...
    try: ... PUT ...
```
`_fetch_main_html()` 内 `urlopen` 抛的网络异常（实测 `FileNotFoundError` / 连接截断）**未捕获逃逸**
⇒ Traceback ⇒ exit 1（故日志是 Traceback 而非 SystemExit）。**且原实现不校验正文完整性**：
`read()` 中途截断时（实测 1286885 / 1338126 / 1336976 / 1291766 字节 vs 期望 1352965）会拿
**残缺 html 去 PUT，可能写坏线上 index.html**。本步已是 bug 温床（09-22 刚修过它凭空引用 `t` 的 NameError）。

**修法三件**：
1. 取正文纳入 `try` ⇒ 失败走 3 次重试而非崩溃；
2. **完整性断言**（尾必须 `</html>`）⇒ 宁可不改，绝不写坏线上；
3. workflow 侧挂 `continue-on-error: true` ⇒ ?v 同步属次要动作，失败交 reconcile 自愈，
   **绝不阻断链尾机器校验**（与 cn fetch「软失败 + 强制告警」同范式）。

**自检**：YAML 合法 / step 16→16 名称序列一致 / inline python `ast.parse` 通过 / 6 项关键点全绿；
推送走 Git Data API（漂移断言 + 回读 83489 B sha256 一致）。
**验证态势**：21:18 那拨（`#35866103777`）在我推送前已 checkout ⇒ 仍跑旧码，**不作样本**；下一拨起用新码。
