### 🔴 Bug ① `permissions: actions: read` → dispatch 必 403

| yml | actions 权限 |
|---|---|
| `v8_cn_fetch_watchdog.yml` | **write** |
| `v8_slot_scheduler.yml` | **write** |
| `v8_freshness_watch.yml` | **write** |
| `v8_algo_cloud.yml` | **write** |
| **`v8_cn_fetch_intraday_lemoncat.yml`（原）** | **read** ← 唯一异类 |

用 `GITHUB_TOKEN` 调 `POST /actions/workflows/{id}/dispatches` 需要 `actions: write`。
原写法会让**每一档都 403 失败 → 14 档全白跑 + 每档一条 `::error::` annotation → 制造 14 个红灯**。
✅ 已改为 `actions: write`（`contents` 保持 read，本 yml 不写盘不 push）。

### 🔴 Bug ② 云端 dispatch 失败时，cn 兜底**永远不会触发**（最致命）

原条件：
```yaml
if: steps.check_cloud.outputs.need_fallback == 'true'
```
但 `check_cloud` 自身的前置条件是 `if: steps.dispatch_cloud.outputs.ok == 'true'`。
→ **云端 dispatch 一失败，sleep / check 两步都被跳过，`need_fallback` 从未被赋值 → 空串 != 'true' → 兜底不执行。**
恰好是"整条云端链挂掉"最需要兜底的场景。

✅ 已改为：
```yaml
if: steps.dispatch_cloud.outputs.ok != 'true' || steps.check_cloud.outputs.need_fallback == 'true'
```
显式覆盖两种情形：①云端 dispatch 失败 ②dispatch 成功但云端跑失败/超时/无 run。

### 🔴 Bug ③ `python3` 在 cn 机上不存在

小九 cn runner 是 Windows + Git Bash。同机其他 yml 一律用 `python`：
`v8_cn_fetch_cloud_selfhosted.yml` / `v8_lhb_fetch.yml` / `v8_stock_quote_refresh.yml`。
✅ 已改为自动探测：`PY_CMD=$(command -v python3 || command -v python || echo python)`
