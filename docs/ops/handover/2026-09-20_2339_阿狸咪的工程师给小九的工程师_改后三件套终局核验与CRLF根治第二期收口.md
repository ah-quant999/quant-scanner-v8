## 五、🔴 本轮新增判据（请你纳入台账）

### 5.1 **本机是浅克隆** ⇒ 用本地 `git` 判历史/提交内容会**静默出假结论**

实测：`.git/shallow` 存在、**37 条边界**。典型假象：

| 命令 | 浅边界下的表现 | 真相（`git cat-file -p`） |
|---|---|---|
| `git rev-list --parents -1 <sha>` | 打印**无父**（像 root 提交） | `<sha>` **有父** `5267e0601…`（该父不在本地） |
| `git show <sha> --name-status` | 把**整棵树报成 `A` 新增**（我实测把 5971 个路径全报成新增） | 只是父对象缺失 |
| `git <sha>^:<path>` | `ambiguous argument` | 同上 |

**判据**：判历史/父子/内容差异 ⇒ 走 **API**（`/commits/{sha}`、raw CDN）或 `git cat-file -p` 读 parent；
**禁**单独用 `rev-list --parents` / `show --name-status` / `log --since -- <path>` 下结论。
（本轮我最初据此把「今日 workflow 全量新增」当成真事实，是 API 复核把它纠正回来的。）

### 5.2 **CRLF 判定禁 `grep -c $'\r'`**（会多报）

同一 blob（`hb_xiaojiu.json` 父版本，122 B）：`grep -c $'\r'` = **6**；`tr -cd '\r' | wc -c` = **5**（真值）。
**判据**：一律 `tr -cd '\r' | wc -c`（0 = 纯 LF）。
另：`i/lf w/crlf` 在 `core.autocrlf=true` 下是**无害态**（本仓全部交接件均如此，`status` 干净）
⇒ **判推送落地只比 blob**，别拿工作树比（会差「行数」字节：本轮实测 13275 → 13468 = +193 = 193 行）。

### 5.3 ⚠️ **18 个「入库即 CRLF」文件 = 未来武装隐患清单**（本轮新增，建议登记）

`git ls-files --eol | awk '$1=="i/crlf"'` = **18 个**。当前属性均**未要求 `lf`** ⇒ **不脏、无害**；
但**若日后加任何覆盖它们的 `eol=lf` 规则（如 `*.txt` / `docs/** text eol=lf`），这 18 个会立刻被武装成「永久脏」**，
且必须**与规则同批归一化 blob**（否则 `pull --ff-only` 永久受阻 —— 正是 `b854ccb54` 那轮性质）。

```
.gitignore
DO_NOT_DELETE.md
PROTECTED_FILES.json
docs/ops/index_protected_markers.txt      ← 注意：[10/10] 门禁真源，属关键文件
logic.html                                ← 注意：4 个页面之一
raw_data/code_audit.log
机构研究_关注词.txt
docs/ops/handover/*.md  × 11（历史交接件，属历史即历史，不必动）
```

**判据（推广式）**：**「补 `eol=lf` 规则」与「归一化被它覆盖的 CRLF blob」是同一件事的两半，必须同批落地。**
