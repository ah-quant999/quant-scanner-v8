## 一、结论（一句话）

**不是「门槛该不该放宽」，而是代码把主人的口径实现错了。**
主人原文判据是「**4/5 连续 5 年**」，代码写成「**全程年份占比 ≥ 0.8**」。
数据从 5 年积累到 8 年后，后者自动变成「8 年里需 7 年」，

## 三、为什么不能简单「放宽到 6/8」

顺带否证一个看似合理的替代方案（防以后有人再提）：

- 若改成「6/8」，则**一个因子都放不进来**（最好的只有 5/8）⇒ **放宽是无效动作**；
- 若改成「5/8」，二项检验（真实无效因子 p=0.5）下 `P(≥5/8) = 0.3633`
  ⇒ 8 个因子里**期望有 2.9 个是蒙对的**，**等于放进噪声**。

⇒ **「按比例改阈值」这条路两头不讨好。真正的修法只有一个：回到「连续 5 年窗口」的原口径。**

## 四、实际处置：恢复主人原口径（已执行）

### 4.1 改动内容（commit `10194b24`）

1. 新增常量并写明「不得改回全程占比」的留痕原因：
   ```python
   WIN_YEARS = 5          # 判定窗口长度（年）
   WIN_PASS_N = 4         # 窗口内需达标年数
   ```
2. `pass_yr` 改为滑动窗口（取最优窗口）：
   ```python
   _yr_seq = [1 if years[y]["beat_base"] > 55.0 else 0 for y in sorted(years.keys())]
   if n_y >= WIN_YEARS:
       win_best = max(sum(_yr_seq[s:s + WIN_YEARS])
                      for s in range(len(_yr_seq) - WIN_YEARS + 1))
   else:
       win_best = n_ok          # 数据不足一个窗口 ⇒ 按现有年份原样判（不虚增门槛、不放宽）
   pass_yr = (n_y > 0 and win_best >= WIN_PASS_N)
   ```
3. 输出补字段 `win_years` / `win_pass_n` / `win_best_ok`，供前端如实展示。
4. `criteria` / `methodology` 文案与实现对齐。

**判据数值精神未变**：仍为 4/5、>55%、IR_OOS>0.3。只把「全程占比」改为「连续 5 年滑动窗口」。
