## 一、#268 休市段第2天云端问责必红 —— 已根治并上线 ✅

### 1.1 根因（一句话）
各批脚本用 `now`（实际运行日）写 `update_time`，但问责步 `v8_stage_gate.py --recheck --today <chain_day>` 的 `chain_day` 是休市段段首（如 09-19），而 `decide()` 真实产出日却是 09-20（周日）。`check_ready` 判据 `c[0]==day` 永不满足 → `ready_ok_B=false` → RC=1 → run 必 failure。

**附加陷阱**：`main()` 收到 `--today` 后把 `now` 的日期覆盖成数据日，导致 `now.date()` 不再是真实运行日 —— 这是本轮调试中发现的实质坑，已在 `main()` 用独立 `_run_day`（取真实当前 CST 日期，不被 `--today` 污染）修正。

### 1.2 修复（commit `70d9a5e8f93b`，已推 main）
- `check_ready` 加 `run_day` 参数 + `_run_day_tol` 容错：运行日≠数据日时，产物戳落在运行日也判 OK。
- `decide()` / `_backfill_candidate()` 全部透传 `_run_day`。
- `v8_algo_cloud.yml` 问责步加 `v8-algo-holiday-2nd-day` `::notice`（不改 RC，仅可见化说明「合规非故障」）。
