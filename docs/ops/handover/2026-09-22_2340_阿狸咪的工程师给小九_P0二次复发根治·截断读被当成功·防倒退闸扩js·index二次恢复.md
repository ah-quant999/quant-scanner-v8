1. **HANDOFF 追加点**：本文件**以最后一项结尾、无尾部 meta 段**。把插点算成「最后一条 `  - id:` 行之后」
   会把**最后一项的块劈成两半** ⇒ 该块只剩 id 行 ⇒ `[13/13]` 报「缺 priority/owner/status」。
   正解 = **EOF 追加**，并断言「除目标项外所有块逐字节不变」。
2. **新项 schema**：结构要求含 `owner`（缺则 `[13/13]` 直接结构违规）。
3. **负向用例方向**：`next_id_seq` 判据是「YAML ≥ ledger」，故负向用例必须让 **ledger 侧更大**；
   我第一版写成 ledger=10 / YAML=58 ⇒ 58≥10 本就该放行，**是我用例错，不是判据失效**。
4. **`id_content_hashes` 口径未能复现**：旧 ledger 的哈希与本机任何归一化变体（sha256/sha1/md5/blake2b ×
   rstrip/strip/CRLF/去 updated 行/折叠空白）**均不相等**。按「不做无谓漂移」原则，本轮
