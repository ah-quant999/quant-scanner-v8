## 二、LHB 失真根因（两个独立 bug 叠加）

### 根因 A · 转换层把有数据的产物误判为空（致命）

`update_v8.py::_is_raw_empty_or_stale()` 判空逻辑只看三个字段：

```python
if obj.get("validity") == "unknown": ...
if obj.get("total_scanned") == 0 and mc.get("validity") not in ("ok","good","normal"):
    return (True, "0命中且数据源有效性异常")   # ← LHB 命中这里
```

但 `raw_data/lhb_data.json` 的结构是 `{date, update_time, stocks, summary}`
—— **stocks 里有 66 条真实数据**，只是没有 `total_scanned` / `market_context`。

→ 被判「0命中且数据源异常」→ `build()` 跳过重建 → `data/LHB_DATA.js` 长期停在 0 条。

**这是最典型的「静默失真」：源数据一直有、转换层一直丢、审计一直绿。**

**修复**：dict 中含 `stocks / data / list / items / rows` 任一非空列表 → 一律放行（不判空）。

### 根因 B · 抓取层字段名写错（价格恒为 0）

`algorithms/fetch_lhb.py::_parse_lhb_list_em()`：

```python
'price': float(row.get('最新价', 0) or 0),   # ← 错
```

实测 akshare `stock_lhb_detail_em(start_date, end_date)` 返回的列名是 **`收盘价`**，
不是 `最新价` → `row.get('最新价')` 恒为 None → **所有龙虎榜价格 = 0.0**。

（这正是 `verify_data_sanity.py` 昨晚报的 `LHB_DATA price=0.0` 的来源。）

**修复**：`float(row.get('收盘价') or row.get('最新价', 0) or 0)`，兼容新旧列名。
顺带把 `if __name__ == "__main__"` 下的 `from fetch_logger import ...` 改为 try/except 降级
——该模块在轻量环境缺失时会直接阻断抓取。
