## 二、根因（为什么"写着今天16点多却没数据"）

龙虎榜(LHB) 数据由交易所 **~17:30** 才发布。但 `fetch_lhb.py` 在 **16:xx 的 cn fetch** 就抢先跑了（早于发布时刻），抓到的是**昨日**数据：

- `window.LHB_DATA.date = 20260916`（昨日数据）
- `window.LHB_DATA.update_time = 2026-09-17 16:18:08`（今日抓取时刻）

旧时间胶囊用 `_uBadge('auto','短线', updateTime)` 传 `update_time`，即显示「今日 16:18」。于是出现悖论：
- 胶囊写「今日 16:18 已更新」→ 主人以为今天应有数据；
- 但今天(09-17) 这个格子为空（当日龙虎榜未发布，`LHB_HISTORY['2026-09-17']={trading:false}`）；
- 实际数据在（9 月 09-01~09-16 共 12 天均有，本次实测 `_rcDays()` 返回 70 个交易日，最新数据日 = 2026-09-16）。

**结论**：bug 不在数据缺失，而在时间胶囊语义错误——它显示了"文件抓取时刻"，而非"数据真实所属交易日"。

## 三、一劳永逸修复（已本地 + 线上双验证）

在 `_rcDays` IIFE 内新增纯「数据日期」标签函数（**无"未发布"暗示**，避免重蹈 2026-09-04 删除同名函数的覆辙）：

```javascript
window._rcDataDateBadge = function(){
  var days = window._rcDays() || [];
  if (!days.length) return '<span ...>数据待加载</span>';
  var last = String(days[days.length-1].iso);          // 最新"有数据"交易日
  var disp = last.length===10 ? last : (last.length===8 ? last.slice(0,4)+'-'+last.slice(4,6)+'-'+last.slice(6,8) : last);
  return '<span ...>📅 数据日期 '+disp+'</span>';
};
```

TAB1 / TAB2 共 **4 处**全部改显「数据日期」：
1. TAB1 标题胶囊（行 ~3498）：`_uBadge('auto','短线', updateTime)` → `window._rcDataDateBadge()`
2. TAB1 页脚（行 ~3801）：`'生成日期：'+(updateTime||'--')` → `'数据日期：'+(dataDateIso||'--')`
3. TAB2 标题胶囊（行 ~3936）：原 `update_time` badge → `window._rcDataDateBadge()`
4. TAB2 页脚（行 ~4187）：`'数据更新：'+(LHB.update_time...)` → `'数据日期：'+(_rcDays()最新iso)`

数据渲染逻辑**未动**——日历照常画、股票照常列，仅时间胶囊与页脚口径纠正。
