## 七、判据新增（本轮 3 条）

* **判据 99**：**「脚本已推 main」≠「下次抓取用新脚本」**。CI 抓取流程用**检出时的树**里的脚本；
  缓存戳提交与抓取之间存在同文件其他提交时，会出现「**新脚本产物被旧脚本回写覆盖**」的**反向丢失更新**（产物层面字段被删，而 commit 与 step 全 success）。
  ⇒ **凡「改了抓取脚本」都必须在 workflow 内加「产物字段存在性断言」**，不得只依赖「脚本在 main 上」。
* **判据 100**：**「产物缺字段」优先查「最后一次写产物的 run 的 `head_sha`」**，而非查「最新提交」。
  唯一可靠口径 = `run.head_sha` → 该 commit 的脚本体（`contents?ref=<sha>`）+ 逐字节比对 `parse_note_meta` 之类**特征串**。
* **判据 101**：**穷举结论必须声明扫描面**。例：「根/一级 py 181 + workflow 30 = 211 文件」下的「2 处派发点」**不得**表述为「全仓 2 处」。
