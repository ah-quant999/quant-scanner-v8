### 2. 病灶（4 项，同一条根因链）

数据真源里写的标签形态，与本函数认的形态**不一致**：

| 数据实际写法 | 旧实现认的写法 | 后果 |
|---|---|---|
| `【本人判断】这是三条…`（**方括号、无冒号**，可位于行中或 `- ` 之后） | 只认 `本人判断：`（全角冒号） | 匹配不到 ⇒ **与正文连写**、标签不出现、不加粗。**「没另起一行」和「不加粗」两种投诉同源** |
| `① 光互连：光博会之后…`（圈号条目，**无「主线」前缀**） | 只认 `主线一：` 与 `1）` | 落到普通段落 ⇒ **不加粗** |
| `【一句话结论】` 标题行 | 无状态 | 其下正文段**不加粗** |
| `- 机构观点：…` | 标签切分不剥行首 `- ` | 每次渲染切出 **4 个孤零零的 `-`** 小段（顺带修掉的历史瑕疵） |

### 3. 改法（源码层，共 3 处；行数 84 → 103）

1. `_richSplitLabels()`：标签匹配同时支持 `标签：` 与 `【标签】` 两形态；命中记录改为 `{i, m, span}`（**重叠判定必须用实际命中串长度 `span`**，不能再写死 `m.length + 1`，否则 `【机构观点层面】` 会把 `【机构观点】` 挤掉造成切错丢字）。
2. `renderLines()`：
   - 新增圈号分支 `mCirc = raw.match(/^([\u2460-\u2469])\s*(.*)$/)` ⇒ 序号金色 + **整行加粗**；
   - 标签切分前先剥行首 `- `（`raw.replace(/^[-\u2022]\s+/, '')`）；
   - 新增状态 `_bold`：遇 `【一句话结论】` 置位 ⇒ 其下正文段整段加粗，遇下一个 `【标题】` 自动复位；
   - `本人判断` 标签段的正文一并加粗（标签本身原就是 800）。
3. 保持一行未动：`- 事实：…`（bullet）、`【小节】`（绿色标题）、`1. 2. 3.`（金色序号）等既有分支行为不变。
