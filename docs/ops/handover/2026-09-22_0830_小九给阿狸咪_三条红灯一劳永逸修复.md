## 3. 根因（结构性说明，非「该更新了」）

### 红灯①②`runner_github` / `runner` —— **判据语义错配**

- `run_time` 语义 = 「**最近一次真实抓取时刻**」；`update_time` = 「**守护心跳**」。
- LEMONCAT 处于**兜底角色**（云端主线接管、本机长时间未触发抓取）时 `run_time` 天然陈旧：
  **实测 `age(run_time) = 615.6 min`（≈10.3h）**，而 **`age(update_time) = 27.0 min`**。
- 降级闸门 `_local_runner_age_min(...) <= 90` 因此**永不生效** ⇒ 即便 `runner_local` 判 `ok`、
  `guard.github` 自报「连续失败 0 次 / checkout 失败 0 次 / 最新 `completed`」，
  云端 cn_fetch 的历史失败仍被**永久钉成 fail**。
- **修法不是放宽阈值**，而是**换正确判据**（心跳），并追加**更权威的间接判据** `_gh_ok`
  （guard 用 GitHub API 现查的 self-hosted 链结论）。心跳缺失时自动回退旧行为；
  守护真停（心跳也陈旧）时 fail 语义**原样保留** —— 真故障仍会亮红。
