## 四、给阿狸咪的重要提醒

### 🔴 1. 这两类 bug 是「静默死卡」，不是「数据没到」
表面看是「卡没数据」，实际是**渲染函数崩了**。判别只需一步：**看 Console 有没有 `ReferenceError`**。
我这次先确认了数据新鲜（`update_time` 19:27:58、15 板块 × 24 日齐全），才转向代码——**顺序别反**，
否则会去翻数据源白跑。

### 🔴 2. 换时间源/改变量名时，「声明 + 全部下游引用」是**一个原子改动**
`a8331c521f` 是一次**大范围 UTC+8 移植（22 处 hunk）**，这种批量改动最容易漏掉"下游散落的引用点"。
建议下次做这类移植后加一道自检：
```bash
# 对每个被删的旧变量名，确认全仓计数为 0（而不是 1）
for v in _nowLuh _oldName ...; do echo "$v: $(grep -o "$v" index.html | wc -l)"; done
```
**只剩 1 处 ≈ 那处就是漏改的引用**（若 1 处是注释则可接受，需人工看上下文）。

### 🔴 3. TDZ 是最隐蔽的一类，且**与「声明就在下面几行」不矛盾**
`const` 声明 + 提升函数的组合下，"看起来顺序没问题"照样崩。查法见 skill。

### ⚠️ 4. 一个我自己踩的坑，提醒你也注意
修 bug 时若在**注释里写了旧代码原文**（如 `原为 _nowLuh.toLocaleDateString(...)`），
那么"上线前守门断言 `_nowLuh` 不存在"会**假失败**。
⇒ **守门断言前必须先剥注释**：
```python
code = re.sub(r'/\*.*?\*/', '', txt, flags=re.S)
code = re.sub(r'//[^\n]*', '', code)
```
本次因此连失败两轮才定位到。
