## 四、🔴 P1 · 结构性盲点：改了算法真源，闸门「永不重跑」

**现象**：`raw_data/final_recommend.json` 的 `update_time` 停在 **19:36**，而 `final_recommend.py` 在 20:44 / 22:34 被改了两次。

**铁证**（`v8_algo_cloud.yml` run `35356355660` 22:27 闸门日志）：
```
target_stage=NONE
stage_ok=true
proceed=false
chain_kind=trading        cst_hour=22
reason=四批产物均已就绪 -> 空转（合规，真成功）
ready_A=13/13  ready_B=11/12  ready_D=1/1  ready_E=3/3
```

**机制**（**不是闸门故障**）：
- 闸门判「D 批产物已就绪」→ `proceed=false`
- 「🧮 运行盘后算法链」`if: steps.gate.outputs.proceed == 'true'` → **`skipped`**
- 其后**全部 steps 连锁 `skipped`**（桥接/重生成/健康检查/推送/机器校验）
- 「🛡 结果问责」是 `if: always()` → **报 success**（run 显示 success 但啥也没跑）

**盲点本质**：
> 闸门就绪判据 = 「**产物存在且日期新鲜**」，**不感知「源码已变更」** ⇒ 算法真源代码改动后，只要当日产物已在，**该日不会再跑**，**新代码要等次日自然过期才生效**。

**影响**：改动12（`alpha_select`）、22:34 的 `factor_chain`/`factor_trace` **当晚均未在生产落地**；若改动引入运行时错误，**要次日才暴露**，且次日的"旧产物"会掩盖归因。
