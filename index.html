⚠️ 第②维为何不用「止盈止损」卡的兜底公式（2026-08-12 修正）
🎯止盈止损卡在缺精算数据时会回退 止损位 = 现价×(1-7%)（创业/科创/港股 10%）。这个位置随现价浮动，与现价永远保持 7% 恒定距离——代入「距止损 <5%」判定则恒为 7%、永不成立，「已跌破」更不可能，整维退化成死代码。
因此操作信号只认与现价无关的绝对锚点：① STOCK_STOP_DATA 精算位（近20日窗口 + 固定10%止损 + R:R=1.5，当前仅收录少量个股）；② 我的持仓成本（成本×(1-7%) 为止损线、成本×(1+10.5%) 为目标线）。两者都没有时整维静默、不出信号，绝不用无信息量的公式伪造判断。
推论：非持仓且未被精算收录的股票，第②维不参与打分——这是正确行为，不是缺陷。持仓股则一定有止损/目标判断，正好覆盖最需要纪律的场景。

📈回测胜率与买卖建议 - 口径说明

胜率计算口径
所有回测引擎统一采用 win / (win + loss)，平盘（收益=0）不计入胜率分母。避免一处平盘算输、另一处平盘剔除导致的口径打架。
幸存者偏差控制
通达信 60 日回测会累积每日金股池快照，用「最近 90 天内所有快照的并集」作为回测宇宙。这样可以纳入那些曾经入选、后来跌出池的股票，降低「只测现存强势股」导致胜率高估的问题。快照累积不足时，面板会标注「仍含幸存者偏差」。
买卖建议原则
驾驶舱给出的「最佳持有期」优先看胜率，但同时要求样本量足够。小样本信号不会直接推荐，避免偶然性。

📊CRDS 逆势龙头 - 算法说明

定位
在大盘大跌/震荡市中，捕捉「逆势涨停」的强势龙头股。盘后看(基于日K) · 短线捕捉逆势龙头 · 日频(每日盘后跑)。逆势龙头只在大跌/震荡市有效，若今日大涨则信号参考意义极低。
输入与数据源
· 个股池：watch_result.json（来自 scanner.py watch 模式，即金股池/观察池股票），按数字代码去重。
· 个股K线：mootdx 通达信直连 bars() 为主（不受 BaoStock 封禁影响），东方财富 push2his K线 为兜底。
· 大盘：上证指数 000001 近10日K线。
· 注：mootdx.bars() 每约50次调用重建客户端+gc 以规避 socket 泄漏；CRDS 约需 176 次调用，必须周期重置。
三个核心条件（满足越多越好）
条件判定阈值/口径
① 10日≥2板近10个交易日涨停次数 ≥ 2主板涨停阈值 9%（留1%误差）；创业板/科创板 18%
② 大跌日逆势板至少1个涨停日对应大盘当日跌超阈值MARKET_DOWN_THRESHOLD = -1.5%
③ 量能确认量价比 VR 峰值 ≥ 1.5VR = 当日成交额 / 近20日均成交额
打分公式
AF = max(涨停且大盘跌那天的 个股涨幅 / |大盘当日跌幅|) # 大盘跌幅需 > 0.5% 才计 VR_peak = max(近10日成交额 / 近20日均成交额) TS_peak = max(近10日换手率 / 近20日均换手率) 逆势板占比 = zt_on_down / zt_count CRDS_raw = AF × min(VR_peak, 3) × (1 + 逆势板占比) / 3 CRDS_score = min(100, round(CRDS_raw × 10)) # 归一化并截断到 0~100
分层（按满足条件个数 conds 0~3）
· 精选级 (3/3)：elite，无条件优先看
· 进阶级 (2/3)：advanced，差1步
· 关注级 (1/3)：watch，仅放量2连板/非逆势（评分均0时前端标注折叠去噪）
大盘环境有效性判断（决定信号可信度）
上证今日涨跌幅有效性含义
≥ +2.0%失效大涨市无需逆势龙头，信号参考意义极低
+1.0% ~ +2.0%低效市场偏强，CRDS 有效性降低
-0.5% ~ +1.0%有效震荡市，CRDS 可正常参考
-2.0% ~ -0.5%较有效市场偏弱，CRDS 较有效
< -2.0%高有效暴跌恐慌市信号最强，但需防系统性风险
待机提示文案（无逆势板时显示）
大盘档卡片待机文案
高有效 / 较有效🟡 当前无逆势板信号 — 今日大盘偏弱但暂无个股逆势涨停，CRDS 逆势模型持续监控中
有效（震荡市）🟢 当前大盘震荡，暂无逆势板信号 — 震荡市 CRDS 可正常参考，模型持续监控中
低效⚠️ 市场偏强，CRDS 有效性降低 — 暂无需逆势龙头，信号参考意义有限
失效🔴 今日大涨，逆势龙头不适用 — CRDS 参考意义极低
其他⏳ 当前无暴跌日 — CRDS 逆势模型持续监控中
名字清洗（防研报/新闻稿污染名）
卡片绝不出「看好/完成/给予」等研报词垃圾名。优先级：东财 f58 权威名 > 通达信名字(仅股票段且非指数/债) > raw 干净名 > 退化代码兜底。
与「涨停热力矩阵」的区别
涨停热力矩阵：10日概念板块涨停家数热力矩阵，看板块热点持续性。
CRDS 逆势龙头：单只个股的逆势涨停强度评分，看个股逆大盘的龙头成色。维度不同、不重复。
输出链路
calc_crds.py → data/crds_result.json → update_v8.py 注入 window.CRDS_CARD_DATA → 前端「逆势龙头」tab 渲染（含历史扫描累积追踪）。

③ 调度韧性设计

双保险调度：云端 4 workflow 原生 cron 定时 + 本机发令枪每 15 分兜底 dispatch（互为备份）。发令枪跑在本机，不受 GitHub Actions 禁用影响。
发令枪 4 档：每小时 :00/:15/:30/:45 各一发令枪，覆盖 09:00–19:00 全交易时段，云端任一档位沉默即被唤起。
Concurrency 锁：所有 workflow 按调度档位分组互锁（同一档位串行，不同档位不互杀），根除大范围 cancelled。
容错设计：除"抽页/同步/同源校验"等严格步骤外，所有数据抓取/计算步骤均设续跑保护，单个步骤超时/失败不会使整个 job 失效、不累积禁用性失败计数。
新鲜度闸门：部署前对比线上数据时间戳，若本地不比线上新则跳过部署（但不判 job failure）。
冲突检测：每次部署前扫描 origin/main 的 data/ 目录是否有 git 冲突标记残留，有则阻断部署。
兜底层级：云端原生 cron → 发令枪 API dispatch → 双机定时(08:45/每:40/16:31/19:30) → 19:30 守卫部署。任一层失效，下一层 30 分钟内自动顶上。

📊 CRDS 逆势龙头评分（暂未上架区）

CRDS = AF × min(VR, 3) × (1 + 逆势板占比)
AF = 逆势强度（个股涨跌 / |大盘涨跌|）
VR = 量价比（涨停日成交额 / 20日均成交额，封顶3倍）
逆势板占比 = 大跌日涨停数 / 10日内总涨停数
归一化后 CRDS 评分范围 0~100，三项条件全满足的进入"精选级"。

📌 结论
• 条件②只有在大盘跌幅 ≤ -1.5% 的交易日才会被触发；其余三种天气下条件②必然为 false，精选级无数据。
• 如果今天大盘只跌 -0.8% 或涨 +0.5% → 进阶级（条件①+③）正常出，但它本质就是"10日内有2板的放量股"，等同于你系统里既有的短期强势动量，不是新信息。
• CRDS 是"恐慌刀"：日常晴天用普通扫描/多维共振即可；只有市场单日暴跌 ≥-2% 或连续阴跌时，CRDS 才能从 73% 的下跌股里捞出 2% 逆势封板的金子。
• 大盘连续阴跌 → CRDS 累积信号最强（一次 2 板 + 一次逆势 = 双重确认的强势股）。
