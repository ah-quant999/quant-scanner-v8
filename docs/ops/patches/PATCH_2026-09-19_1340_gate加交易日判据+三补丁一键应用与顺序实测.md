## 一、为什么要改（实证，非推测）

`build_deploy` 的 `gate` 判据（`v8_build_deploy.yml` L100-103）**只有时钟窗，没有任何星期/交易日维度**：

```bash
TH=$(TZ=Asia/Shanghai date +%-H); TM=$(TZ=Asia/Shanghai date +%-M)
TR=0
if { [ "$TH" -eq 9 ] && [ "$TM" -ge 25 ]; } || [ "$TH" -eq 10 ] || { [ "$TH" -eq 11 ] && [ "$TM" -le 30 ]; } || [ "$TH" -eq 13 ] || [ "$TH" -eq 14 ]; then TR=1; fi
```

后果（我方 11:55 档，09-19 全天 28 个 run 的实测矩阵）：

| 事实 | 证据 |
|---|---|
| 唯一被判 `trading=true` 的 `#7073`（10:34:05）正是**唯一** `build=skipped` 的那个 | 逐 run 复算 L102 判据 × `build` 真实结论 = **28/28 一致** |
| ⇒ 排除偶发/并发/超时解释 | 这是判据自身的**确定性行为** |
| `run` 顶层 conclusion 仍为 `success` | **假成功**：看 run 结论会误判「已部署」 |
| 手动 `workflow_dispatch` **同样被 skip** | build 的 `if` 白名单含 `workflow_dispatch` |

**⇒ 直接命中主人诉求的失败机制**：主人「周末手动跑更新和部署」，在 09:25–11:30 / 13:00–14:59（CST）两个窗内**结构性不跑 build 且 run 全绿**。

## 二、补丁内容

```bash
# 新增 DW（星期）与 TD（交易日）两层短路；原时钟判据一字未动
DW=$(TZ=Asia/Shanghai date +%u)     # 1..7（6=周六，7=周日）
...
IF_TD="${{ steps.td_run.outputs.is_trading_day }}"
if [ "$DW" -ge 6 ]; then TR=0; fi              # 短路一：周末（离线可判、确定）
if [ "$IF_TD" = "false" ]; then TR=0; fi       # 短路二：日历明确非交易日（含法定假日/调休）
```

新增两步（插在原 `t` 步骤**之前**，原有判据步骤保留）：

| 步骤 | 作用 |
|---|---|
| `td` | `actions/checkout@v4` + **稀疏检出**（仅 `algorithms/check_trading_day.py` + `v8_date.py`）|
| `td_run` | `python algorithms/check_trading_day.py \|\| true` ⇒ 输出 `is_trading_day` |

`outputs` 增加 `is_trading_day`（可观测）。

### 🔴 安全边界（本补丁最关键的一条）

**日历步骤失败 ⇒ `IF_TD` 为空 ⇒ 不降级，保持原时钟判据。**

理由：若把「取不到日历」当作「非交易日」，那么**工作日盘中只要日历接口抖动，全量 build 就会在盘中开跑**，复发
2026-09-03 的盘中风暴 —— 而那个风暴正是这道闸门当初要根治的对象。同时 `td` / `td_run` 均带
`continue-on-error: true`，避免 checkout 或日历异常掐断 `gate` 从而让 `build` 全停。

**收益矩阵**：

| 场景 | 改前 | 改后 |
|---|---|---|
| 工作日盘中（push / workflow_run） | `trading=true` ⇒ build 不跑 | **不变**（保留盘中风暴根治） |
| 工作日盘中（手动派发） | 被 skip | **不变** |
| **周末**（任意触发） | 🔴 build 结构性不跑、run 绿 | ✅ `DW>=6` ⇒ build 跑 |
| **法定假日/调休** | 🔴 同上 | ✅ 日历输出 false ⇒ build 跑 |
| 日历接口挂掉（工作日盘中） | — | ✅ 不降级 ⇒ 仍不跑（无风暴风险） |

## 七、🔴 一个必须记住的构造陷阱（本轮踩到并已修）

用「插入型补丁」改 YAML 时，**若插入段的末尾吃掉了原锚点行**（例如把 `- id: t` 吞掉），
结果是：`shell:` / `run:` 变成**同一 mapping 内的重复键**，

- **PyYAML `safe_load` 不报错**（静默取最后一个）⇒ 「YAML 能解析」是**假通过**；
- 语义后果严重：`t` 步骤消失 ⇒ `steps.t.outputs.trading` 为空 ⇒ `needs.gate.outputs.trading != 'true'`
  恒成立 ⇒ **build 恒跑** ⇒ 工作日的盘中风暴会回来。

**⇒ 规则：生成 workflow 补丁后，除 YAML 解析外，必须断言结构序列**（步骤数 + `id` 序列 + 关键字段在位）。
本补丁已内置该断言：`gate.steps 数 = 3 | ids = ['td','td_run','t']`。
