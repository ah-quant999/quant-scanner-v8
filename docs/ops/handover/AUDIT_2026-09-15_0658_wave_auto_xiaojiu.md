## 一、致命缺陷（P0）——阿狸咪 pull 后报告必挂

### 症状

阿狸咪执行 `git pull && python v8/gen_wave_report.py` 时，脚本**直接报错退出**，报告产不出来：

```
✗ 无法解析 data/WAVE_ELLIOTT.js（window.WAVE_ELLIOTT 结构异常）
```

### 根因

仓库约定：`update_v8.py` 用 `json.dumps(..., separators=(',',':'))` 把**所有** `data/*.js` 压缩为**单行**（已核实 `SH_FIB.js`、`TRIPLE_CONSENSUS.js` 同为 1 行，是全局约定，非异常）。

而我 09-14 写的解析正则是：

```python
r'window\.WAVE_ELLIOTT\s*=\s*(\{.*?\n\});'   # ❌ 要求换行 + } 结尾
```

压缩成单行后 `\n}` 永远匹配不到 → 正则返回 `None` → `sys.exit` 报错。

> 我在本地测试时用的是自己写出的**美化多行版**（`indent=1`），所以本地永远通过；一旦推仓库被压缩，阿狸咪侧就挂。**这是典型的"只在本地验证"漏洞。**

### 修复

两个脚本统一改为兼容两种落盘形态：

```python
r'window\.WAVE_ELLIOTT\s*=\s*(\{.*\});\s*$'   # ✅ 兼容多行与单行压缩
```

写入侧（`fetch_wave_elliott.py`）同步改为**直接产出压缩态**，与仓库约定一致，避免被二次重写。

**复验**：从远端取纯净压缩版（1 行）→ 独立目录跑脚本 → ✅ 成功产出报告。

## 二、隐患 2（P1）——产出 HTML 不可移动

### 症状

产出报告在 `out/` 目录，靠相对路径 `../data/WAVE_ELLIOTT.js` 取数。**一旦把 HTML 单独发给别人或移到别处 → 数据加载失败 → 页面白屏**。

### 修复

改为产出**自包含 HTML**：脚本运行时把数据内联进产物，抹掉外部路径依赖。

**复验**：产物 31724 字节，`仍含外部数据引用 ../data/: False`，`已内联: True`。

## 三、隐患 3（P1）——幂等判断基于落后副本

### 症状

幂等判断只看**本地** `data/WAVE_ELLIOTT.js`。若本地落后于远端（本仓工作树常与远端脱节），会**误判「无新交易日」**，进而用**陈旧数据**渲染报告。
