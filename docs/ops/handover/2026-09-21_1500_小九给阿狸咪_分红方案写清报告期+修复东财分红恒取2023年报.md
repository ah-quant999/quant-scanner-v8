- **数据采集时刻**：2026-09-21 13:10–14:40（CST）
- **触发**：主人截图质疑「个股查询里的分红方案是何时的，要写清楚」
- **线上基线**：滚动取 `git/ref/heads/main`；本档不写死任何 sha（本仓分钟级 churn）

## 一、一句话结论

「分红方案」行只显示**裸方案文字**（如 `10转4股；10派21元`），看不出对应哪一期的分红；
而更深一层的问题是：**东财分红数据源被恒定为 2023 年报**，非重点池的票分红已陈旧两年。

---

## 二、根因（两层）

### 根因 A（表现层）：前端只渲染了方案文字，丢掉了所有日期字段

`renderQuote()` 里原本只取 `d.desc` / `d.progress` / `d.ex_date`：

```
const planStr = d.desc || null;      // 10派4.2元
const progStr = d.progress || null;  // 实施分配
const exStr   = d.ex_date || null;   // 除权除息日（财务网格里）
```

数据里其实**早就有**这些字段，只是没渲染：`report_period`（报告期）、`plan_date`（公告日）、
`announce_date`、`record_date`。截至 2026-09-21 13:12 实测 `raw_data/stock_quote.json`：
含 dividend 的 3732 只里，`report_period` 仅 **447 只**有值（且仅限 cninfo 覆盖过的重点池）。

### 根因 B（数据层）：`ak.stock_fhps_em()` 不传参 ⇒ 默认取 2023 年报

akshare 1.18.64 源码 `stock_feature/stock_fhps_em.py`：

```python
def stock_fhps_em(date: str = "20231231") -> pd.DataFrame:
    """东方财富网-数据中心-年报季报-分红送配
    :param date: 分红送配报告期
```

`date` **就是报告期**，且默认值被写死为 `'20231231'`。
而 `algorithms/fetch_stock_quote_v8.py::merge_dividend()` 调用时**不传参**：

```python
df = ak.stock_fhps_em()          # ← 恒等于 ak.stock_fhps_em(date="20231231")
```

⇒ 全市场分红数据**永远停在 2023 年报**。

**实测佐证**（截至 2026-09-21 13:12）：

| 票 | 线上改动前 | 东财最新报告期实测 |
|---|---|---|
| 平安银行 sz000001 | `10派7.19元` · 除权 **2024-06-14** | 2026半年报 · 10派2.49元 · 除权 2026-09-24 |
| 德业股份 sh605117 | （cninfo 覆盖，2025年报） | 2026半年报 · 10派16元 |
| 美的集团 sz000333 | 旧值 | 2026半年报 · 10派5元 |

另实测：线上 `data/STOCK_QUOTE.js`（`update_time` 2026-09-21 11:31:02）**7185 只票里
没有一只带 `report_period`** —— 因为 `fetch_stock_quote_v8.py` 每轮都**全量重建** STOCK_QUOTE，
把 `refresh_dividend_cninfo.py` 之前写入的 cninfo 分红字段整段覆盖掉了。这是**另一条待办**（见第五节）。

## 三、本次改动（4 个文件）

### ① `index.html` —— 分红方案行加时间标注 + NaN 守卫（5 处）

| # | 位置 | 改法 |
|---|---|---|
| P1 | `renderQuote` 股息字段区 | 新增 `repStr`/`planDateStr`/`divWhenParts`/`divWhenTime` |
| P2 | 分支 A（有综合评级） | 方案行末尾追加 `divWhenTime` |
| P3 | 分支 B（无评级但有分红） | 同上 |
| P4 | 股息率 | `d.yield` → `dyNum`（`isFinite` 守卫，防渲染 `NaN%`） |
| P5 | 分红比例行 | 加 `isFinite(d.cash_ratio)` 守卫 |

渲染规则：

```
divWhenParts = [report_period] + [有 ex_date → '除权 '+ex_date，否则有 plan_date → '公告 '+plan_date]
divWhenTime  = 〔… · …〕（灰色小字，紧贴方案徽章之后）
```

### ② `logic.html` —— 同口径同步（6 处）

`logic.html` 里有一份 v6 移植期的 `renderQuote()` 代码节选，**已落后 index.html**
（缺 `divCheck` 分红合理性核查等）。本次只同步「时间标注 + NaN 守卫」这 5 处逻辑，
另加 1 处说明文字（`基本面画像` 条目补「（标明所属报告期与除权/公告时点）」）。
**未**补齐 `divCheck` 等历史差异——那属于另一件事，见第五节待办。

⚠️ `logic.html` **必须保持纯 CRLF**（`crlf=8538 / bareLF=0`，已断言）。

### ③ `algorithms/fetch_stock_quote_v8.py` —— 报告期显式传入（5 处）

- 新增 `_REPORT_TAG` / `_recent_report_dates(n=6)` / `_report_period_cn(p)`
- `merge_dividend()`：改为遍历最近 6 个报告期（`2026半年报 / 2026一季报 / 2025年报 /
  2025三季报 / 2025半年报 / 2025一季报`），`pd.concat` 后 `drop_duplicates(subset=['代码'], keep='first')`
  ⇒ 每只票只保留**最新报告期**那一行
- `desc` 取值改为**东财最新期优先**（原为「已有就保留」，会与新的 `report_period` 自相矛盾）；
  cninfo 刷新步骤在该脚本**之后**执行，仍会以 cninfo 为准覆盖
- `_f()` 加 NaN → None（防前端 `NaN%`）
- 新增落盘字段：`report_period`、`plan_date`

**实跑实测**（2026-09-21 13:20，本机 venv akshare 1.18.64）：耗时 **7.0 秒**，命中 **3809 只**，
产出样例与前端渲染期望完全一致。

### ④ `data/STOCK_QUOTE.js` —— 按同口径回填

规则：**已有 `report_period` 的票完全不动**（cninfo 权威）；其余用东财最新报告期整段替换
（`desc`/`ex_date`/`progress`/`cash_ratio`/`yield` 一并更新，避免「报告期新、文字旧」错配）。

截至 2026-09-21 13:41 实测：`changed=3641` · `keep_cninfo=0` · 东财无记录保持旧值 `1756`（其中原有分红 545）。

> `update_time` 字段**保持原值**未改（行情部分确为 11:31 那批）；下次云端跑
> `fetch_stock_quote_v8.py` 会自然统一。
