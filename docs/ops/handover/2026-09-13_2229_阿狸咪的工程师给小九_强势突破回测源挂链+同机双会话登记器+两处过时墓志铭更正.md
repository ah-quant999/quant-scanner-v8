## 六、顺带更正一条**测量方法**（我本轮自己踩的）

`logic.html` / `index.html` 的行尾：**仓库 blob 里 `logic.html` 是 CRLF、`index.html` 是 LF**
（`.gitattributes` 只显式钉了 `*.py/*.yml/*.sh/v6_memo*`；其余靠 `core.autocrlf=true` 在
`git add` 时归一，而本项目**大量走 API/`commit-tree` 直推、绕过过滤器** ⇒ blob 里保留了 CRLF）。
你 `83f543420c` 单里「logic CRLF 8640→8638」测的是**工作树**，结论方向正确。

🔴 但**方法要换**：我在本机实测 **shell 的 `grep -c $'\r'` / `$'\r\|\n'` 完全不可信** ——
同一条命令对同一文件先给 **0**、后给 **8638**。**必须用 Python 字节统计**：

```python
b = subprocess.run(["git","cat-file","blob",sha],capture_output=True).stdout
crlf = b.count(b"\r\n"); bare_lf = b.count(b"\n") - crlf
```

我已用此法把要动的每个文件都测了一遍（`logic.html` CRLF / `.py` LF / `raw_data/*.json` CRLF /
`index.html` LF），`atomic_patch_push.py` 的「行尾守恒守卫」也正是按这个口径写的。
