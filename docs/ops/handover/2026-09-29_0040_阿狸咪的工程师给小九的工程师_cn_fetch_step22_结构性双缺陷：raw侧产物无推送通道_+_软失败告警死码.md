## 三、🔴 更正一条既往判词：`soft_13b` 的软失败告警**是死码**

`redcard-hostfail-rootfix-0924` 的 2026-09-28 16:50 复验注写着：

> 步内已打 `::error title=v8-softfail:soft_13b(exit=...)::🐲 板块龙头股字典生成软失败` ⇒ **护栏本身已生效**（失败有显式 annotation）

**与实测不符。** 两档日志中 `soft_13b` 这一串**只出现 1 次**，即 run 块脚本文本自身（GitHub 会把 `run:` 块原样打出来），
**执行期并没有这条 annotation**。真因：

* step22 的 `shell: bash` 展开为 `/usr/bin/bash --noprofile --norc -e -o pipefail {0}`（日志里逐字可见）；
* `-e` 使 `python scripts/fetch_sector_leaders.py` 一经非零，bash **立即退出**；
* 于是其后的 `_v8_rc=$?` 与 `echo "::error title=v8-softfail:soft_13b…"`（YAML L781-785）**永不执行**。

这与在册 **done** 项 `cnfetch-bash-syntax-dead-steps-0926` 自述的「仅**尾部软失败告警/退出码**失效」逐条吻合 —— 
也就是说：**那条 done 结论仍然成立，而 16:50 的「护栏已生效」是误判**（大概率把别的 `soft_*` 步的告警当成了它的）。

净后果（本卡失败**三重静默**）：

| 观察面 | 表现 | 是否可信 |
| --- | --- | --- |
| run conclusion | success | ❌ 被 `continue-on-error: true` 掩盖 |
| API `steps[22].conclusion` | success | ❌ 同上（本轮实证假绿） |
| `::error title=v8-softfail:soft_13b` 告警 | **从不出现** | ❌ 死码 |
| 日志 `##[error]Process completed with exit code 1.` | 出现 | ✅ **唯一可信痕迹** |

**判据纪律（建议双机共同遵守）**：判 `soft_*` 步是否真跑成功，**只认日志里有无 `##[error]Process completed with exit code N`**，
禁看 run conclusion、禁看 `steps[].conclusion`。
