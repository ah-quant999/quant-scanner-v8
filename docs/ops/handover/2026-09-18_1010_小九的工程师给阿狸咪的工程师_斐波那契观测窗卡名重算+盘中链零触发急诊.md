## 二、斐波那契卡重算：为什么「距F(?) —」

### 2.1 根因（第三方可复现）

`data/SH_FIB.js` 真身（1100B，实测）：

```
windows: 7 条，status 全部 = "passed"
next_cycle: []
```

生成器 `algorithms/fetch_sh_index_fib.py` 逻辑链：

1. `FIB_BASE_DATE = "2026-05-22"` ⇒ 7 个固定窗口 F(3)…F(55)，最晚 **2026-07-16**，**早已全部走完**；
2. `_roll_forward()` 负责「续命」：全部走完时以 `reversal_date` 为锚点推算下一轮；
3. 但数据里 **所有窗口 `status=passed`**（无 `triggered`），且 `build_windows()` 的
   `reversal_date` 只在 `rev["reversal"]=="confirmed"` 时赋值 ⇒ **锚点为 None**；
4. `_roll_forward` 拿不到 anchor ⇒ `calc_next_cycle` 返回 `[]` ⇒ **续命失败，`next_cycle` 为空**。

前端 `__renderFibWindow` 原实现：

```js
var _fut2=(_fib2.windows.filter(function(w){return w.status==='future';})||[])[0]||{};
```

⇒ 无 `future` 窗口 ⇒ `_fut2 = {}` ⇒ 胶囊渲染 `距 ${_fut2.name||'F(?)'}` ⇒ **永远显示「距F(?) —」**。

**结论：这不是「卡死」，是「本轮窗口已走完、下一轮未生成」被渲染成了无含义的 `F(?)`。**

### 2.2 本批改法（前端渲染层，**未动数据层**）

| # | 改动 | 位置 |
|---|---|---|
| 1 | `_fut2` 三级回退：`future → active → 最后一条 passed`，并新增 `_futIsFuture` 标记 | `index.html` `__renderFibWindow` |
| 2 | 距F 胶囊改双态：有未来窗口显示「**距**F(N) N天」；无则显示「**末窗**F(N) MM-DD」 | 同上 |
| 3 | F窗口 卡内行同步改「📍 下个 / 📌 末窗」 | 同上 |
| 4 | 无未来窗口时追加**金色提示**：`⚠️ 本轮 7 个窗口已全部走完，新一轮尚未生成 · 复核：algorithms/fetch_sh_index_fib.py` | 同上 |

🔴 **口径纪律**：提示语用的是**事实陈述 + 复核入口**，**未写任何「会自动更新 / 会恢复」的预测式表述**。

### 2.3 🔴 未修的一项（留决策，非本批范围）

**`_roll_forward` 的锚点兜底逻辑有缺陷**：其注释号称「窗口全部走完后自动滚动续命：永不让窗口真空」，
但实测**未生效**（`next_cycle=[]`）。修它属于**算法层改动**，会改变 `raw_data/sh_fib.json` 产出，**本批未动**。

> 若要修：给 `_roll_forward` 补「无 confirmed 反转时以 `peak_date` 或最后一条窗口日为锚点」的兜底，
> 并加回归测试。**建议先在本地跑通再上，勿直接改生产链。**
