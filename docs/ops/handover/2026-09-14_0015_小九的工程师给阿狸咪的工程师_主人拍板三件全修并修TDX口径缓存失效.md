## 二、🔴 本次审计新发现并修复的隐性 bug（P0 级）

### `backtest_tdx.py` 的断点续跑缓存 ⇒ **口径改动对既有 221 只股票零生效**

**症状**：我把 `backtest_tdx.py` 重跑一遍，产物 `update_time` 从 13:28 变成 23:41（**确实重写了**），
但 `summary` 里 `total`/胜率/收益**与旧产物逐字相同**。

**根因**（`algorithms/backtest_tdx.py:492-518`）：

```python
existing = json.load(open(OUT, ...))
stock_results = existing.get("stocks", {})
...
if key in stock_results:
    has_all_periods = ...        # 只看「周期字段齐不齐」
    if has_all_periods:
        log(f"  跳过 {name}({key}) — 已有回测")
        continue                 # ← 已回测过的股票整只跳过
```

判据只看「周期字段齐不齐」，**不看口径**。于是你把入场口径改成「次日开盘」后，
221 只既有股票全部被判「合格」而跳过 ⇒ **只有新股票用新口径**，
主数据仍是旧口径，且**没有任何报错、没有任何迹象**。
这是「改了但没生效」的最隐蔽形态（比假挂链更难发现：产物有、时间新、数字正常）。

**修法**（已修，`ENTRY_CALIBER_VER` 单一真源）：

```python
ENTRY_CALIBER_VER = 2   # 1=信号日收盘买入；2=次一交易日开盘买入
...
same_caliber = (old.get("entry_caliber_ver") == ENTRY_CALIBER_VER)
if has_all_periods and same_caliber:
    continue                        # 真·无需重算
if has_all_periods and not same_caliber:
    log(f"  重算 {name}({key}) — 入场口径由 v{old.get(...)} 升到 v{ENTRY_CALIBER_VER}")
```

明细写入时带 `"entry_caliber_ver": ENTRY_CALIBER_VER`。
**以后每次口径变更只改这一个数字，全量自动重算。**

**📌 给阿狸咪的请求**：请复核你参与 P1-1 的另外 4 个脚本是否有同类「按字段齐备度判缓存」的跳过逻辑。
我全局 grep 过 `已有回测|跳过已处理`，**只有 `backtest_tdx.py` 命中**，但你的写法可能用别的字面量，
请以「口径变更是否真的触发重算」为准自行验一遍。
