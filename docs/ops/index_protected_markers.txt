# 【判据 C 的适用边界 · 2026-09-21 实测反面教材，后人务读】
#
# 背景：为补「[10/10] 原为纯子串命中 ⇒ 对『同一卡片内部换回旧版』结构性无感」这一缺口，
#   笔者（阿狸咪的工程师）曾登记一条**布局级**锚点：
#       ms-col ms-note|每日洞察·月度汇总 口径说明第3列容器|2026-09-21
#   结果 **2.5 小时内即被合法改版击穿**（幸而当时尚未推送，CI 未受影响）：
#       06:51 `321b7b98b` 主人令：口径说明落位第 3 列（引入 `ms-col ms-note`）
#       09:00 `4f87d6adf` 主人令：自第 3 列移至第二行通栏（改为 `ms-note-card`；
#                         理由：第 3 列在窄屏会被压成细条、与两卡不同高）
#   ⇒ 锚点 0 命中 ⇒ [10/10] 红 ⇒ **整站 deploy 将被阻断**（本地实测已复现）。
#
# 🔴 结论（三条，均已实测）：
#   1. **布局级 / 样式级特征（class、grid、内联 style、容器结构）严禁登记为锚点。**
#      它们只隔 2 小时就可能被合法 UI 迭代改写 —— 与纪律 3 所禁「活口径文案」同类，
#      且更隐蔽（看起来像「代码级」，实为「布局级」，同样不稳定）。
#   2. **语义/功能级才可登记**：分节 id / 渲染器函数名 / 数据源全局名
#      （如本文的 `window.MAHORO_INSIGHTS`）/ 产物字段名。它们只在「功能被删」时消失，
#      不会因「同一功能改布局」而消失。
#   3. 该卡「口径说明」属**活文案 + 活布局**双重易变 ⇒ **本卡不再新增锚点**；
#      其数据源 `window.MAHORO_INSIGHTS`（见本文 2026-09-20 行）已覆盖
#      「卡片整体被删」这一主要风险。**故本锚点已撤回。**
#
# 【「同卡片内部换回旧版」这个缺口的正解：不在锚点法】
#   锚点法天然要在「拦得住」与「不误伤合法改版」之间二选一：
#     · 锚得越细（布局/文案）⇒ 拦得住回退，但合法迭代必误伤（本轮实证）；
#     · 锚得越粗（语义/功能）⇒ 不误伤，但同卡内部的纯内容回退无感。
#   正解应为 **blob 父子比对**（不依赖任何锚点）：
#     断言「index.html 父 blob ≠ 本 blob 时，二者差异**须含非戳记内容**」——
#     即「只有 `?v=`/`BUILD` 变化却声称改了内容」= 告警；合法改版自然含实质差异 ⇒ 不误伤。
#     可挂 v8_build_deploy.yml 部署前置步。**尚未实现，列为候选，勿当已上线。**
