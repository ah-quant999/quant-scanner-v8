### 2.1 `api_push_raw.py` —— 从「挂死 6 小时」压到「最多 8 分钟」

改动 6 处（**全部最小侵入，不动任何既有守卫语义**）：

| # | 位置 | 改动 |
|---|---|---|
| 1 | 顶部 | 新增 `_PUSH_HEART` / `_IDLE_LIMIT` / `_beat()` / `_start_watchdog()` |
| 2 | `main()` 首行 | `_start_watchdog()` 启动心跳看门狗 |
| 3 | `api()` 签名 | 新增 `timeout=300` 参数（向后兼容），`urlopen` 改用该参数 |
| 4 | 防倒退守卫 | 远端 blob 查询 `timeout=45`（3 次重试最坏 906s → **141s**） |
| 5 | index.html ?v 同步 | `contents/index.html` 查询 `timeout=90`（1.2MB 大响应） |
| 6 | 主循环 4 个出口 | `_beat()` 心跳（内容一致 / 防倒退跳过 / 上传失败 / 上传成功） |

**看门狗语义（关键设计）**：**心跳式**，不是总预算式 ——
只要「每处理完一个文件」就刷新心跳，**正常慢速推送绝不误杀**；
仅当连续 `PUSH_IDLE_LIMIT_SEC`（默认 **480s**）**毫无进展**时才强退。

**为什么强退而非静默跳过**：退出码非 0 才会让 run 失败并**释放并发组**，下轮派发自动续推；
静默 `exit 0` = 假成功，正是主人明令禁止的。已上传成功的 blob 仍在 GitHub 侧，
未提交的 tree/commit 不影响 main ⇒ **强退零数据损失**。

**可调**：`PUSH_IDLE_LIMIT_SEC` 环境变量（若确认只是「很慢」而非挂死，调大即可）。
