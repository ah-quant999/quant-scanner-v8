## 三、修复内容（5 个文件，全部为「补覆盖 + 加断言」，无一处削弱监控）

### 3.1 `v8_stage_gate.py` — B 批 `items` 9 → 11 项
```

+ "data/FOUR_VOLUME_HISTORY.js"
+ "data/FOUR_VOLUME_TRACK.js"
```
- `need` **保持 8**（10→11 项，容忍 2 项）⇒ 60m 是「加分因子」，不因它收紧要挟整条 B 批，
  但**参与计数即可驱散空转**（这才是关键：陈旧会占用容错名额 → 触发重跑）
- `must` **未改动**（三重共识 / 四量终极 / 逆势龙头），不动主人 09-13 拍板的必新项
- 后两项（HISTORY/TRACK）是 09-15 主人令新增的「四量自建系统」，**同型漏登记**，本轮一并补齐

### 3.2 `dedup_fetch_manifest.py` — `_ALWAYS_PUSH` 同步 +3
🔴 **不变式**：`READY_SPEC[*].items ∪ must ⊆ _ALWAYS_PUSH`（该文件 L106 早已立规「零特例，机器可断言」）。

### 3.3 `.github/scripts/guard_double_blind.py` — **NEW · 机读护栏（本批核心）**
把「零特例」从注释里的**纪律**升级为 CI 里的**断言**。三条不变式：

| 不变式 | 校验内容 | 违反后果 |

  降级为 `ⓘ NOTE` **不阻断**；其余未覆盖才算**真盲区**，硬阻断
- 只读静态校验（**不触网络、不改数据**），秒级完成
- **双向测试已做**：负向（修复前文件）准确报出 `FOUR_VOLUME_60M` 等 5 处；
  正向（修复后）**三条全绿**

1. **以 `origin/main` 为唯一真源**。小九机本地工作树是**旧树**（缺本批 P1 修复、缺算法现场评分卡、
   缺本批双盲区修复），**严禁把小九机本地文件当基线推 main**。
2. 本批动的是 **CI/闸门/护栏源码 + 1 个数据产物**，**未动 `index.html`** ⇒ 与你的前端改动**无冲突面**。
   唯一可能撞车的是 `data/FOUR_VOLUME_60M.js`（若你在夜班重跑了 60m，属正常新值，以 `update_time` 新者为真）。
3. **新增 CI 硬门禁**：`guard_double_blind.py` 失败会**阻断部署**。若你在夜班新增/迁移任何
   `data/*.js` 产物到选股类（`heal_cat=algo_run` + `picking=True`），**必须同步**三处：
   ① `v8_stage_gate.py` 的 `items`；② `dedup_fetch_manifest.py` 的 `_ALWAYS_PUSH`；③ 确认不在 `_LOW_FREQ_FILES`。
   **否则 CI 会直接拦下来**（这是设计意图——拦下来比静默停更好）。跑一次自检即可：
   ```bash
   python .github/scripts/guard_double_blind.py
   ```
4. **`CANDIDATE` / `GOLD_POOL` 是已知 NOTE 级**（由采集批产、闸门用 `raw_data/gold_pool.json` 代理），
   护栏不会因它们阻断，**不要误"修"成 items**（会破坏 need 语义）。
