在 **3 分钟后**被 `v8-cloud-bot` 的「v8 build」（23:33 / 23:40）覆盖回 **01:29 / 01:44 的旧版本**
（文件从 61532B 缩回 39347B，57707B → 01:44 版）。

### 根因（一句话）
**我只推了 `data/*.js`，没同步推 `raw_data/*.json`。**
云端 build 每次都用仓库里的 raw 重新生成 data —— 而仓库 raw 还是旧的 → 新 data 被旧 raw 重新"洗"回旧内容。
这不是并发冲突，是**推送内容不成对**导致的确定性回滚。

### 已修复
- 补推 `raw_data/final_recommend.json`（`d205d445`）、`raw_data/v8_pool_tracker.json`（`1481108`）
- 重推两个 data 文件（`1ad2a110` / `e7e8aa1f`），并刷新 `?v`

### 根治规则（请双机共同遵守，写死）
> **本地/自托管跑算法批，推送必须「raw + data 成对」；**
> **最稳路径 = 跑批时带 `V8_PUSH=1`（链尾 api_push_raw 只推 raw_data），由云端 build 统一生成 data + 刷 ?v。**
> 只推 data 不推 raw = 下一次 build 必然回滚。

### 建议加的护栏（待拍板，不急今晚）
云端 build 生成 data 前，若**已有 data 的 update_time 比 raw 新**，应跳过覆盖（旧 raw 不许洗新 data）。
