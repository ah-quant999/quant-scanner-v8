## 二、改动明细（`_pill()` 函数，index.html L2152 附近）

```js
// 改前
var _pill=function(txt,clr){ return '<span style="font-weight:700;color:'+clr+';background:rgba(255,255,255,.08);'
 + 'border:1px solid '+clr+'59;padding:1px 8px;border-radius:6px;white-space:nowrap;">'+txt+'</span>'; };

// 改后
var _pill=function(txt,clr){ return '<span style="font-weight:700;color:'+clr+';background:'+clr+'2e;'
 + 'border:1px solid '+clr+'82;padding:1px 8px;border-radius:6px;white-space:nowrap;'
 + 'box-shadow:0 0 4px '+clr+'99,0 0 10px '+clr+'4d;'
 + 'text-shadow:0 0 5px '+clr+'b3;">'+txt+'</span>'; };
```

| 属性 | 改前 | 改后 | 意图 |
|---|---|---|---|
| background | `rgba(255,255,255,.08)`（扁平灰） | `clr` + `2e`（极淡同色底） | 去扁平感，底色随语义 |
| border | `1px solid clr59` | `1px solid clr82` | 提高锐度，与光晕分层 |
| **box-shadow** | 无 | **`0 0 4px clr99, 0 0 10px clr4d`** | **双层外发光**：近圈强 + 远圈弱 |
| **text-shadow** | 无 | **`0 0 5px clrb3`** | **文字本身也发亮** |

🔴 **发光色 = 胶囊自身语义色**（`clr` 变量），不是写死的固定色。
⇒ 偏弱时红发光、偏多时绿发光、震荡时黄发光；仓位依据同理。**语义一变，发光自动跟着变。**

## 四、踩坑记录（供后续复用）

### 🔴 抽代码段做真渲染时，`return` 会报 `Illegal return statement`
直接从 `index.html` 正则抽出「函数定义 + 拼装段」丢给 `vm.runInContext` 执行，
若原文用的是 `return h;`（在函数体内合法），抽出后成了**顶层 return** ⇒ `Illegal return statement`，**3/3 场景全灭**。
**修法**：抽出后**必须包一层 IIFE**：
```js
const code = '(function(){\nvar h="";\n' + 抽出的定义 + '\n' + 抽出的拼装段 + '\nreturn h;\n})()';
```

### 🔴 判「旧写法清零」的正则要精确到形态，别只匹配颜色
旧写法 `border:1px solid '+clr+'59`，新写法 `border:1px solid '+clr+'82`。
若用 `/border:1px solid #\w+59/` 判定旧写法清零，会**同时命中新写法的 `#ff6b8182` 里那个 `59`?**
—— 不，`#\w+59` 因 `\w` 贪婪会匹配 `#ff6b8182` 吗？实际会匹配到 `#ff6b8159` 这种才叫命中；
但 `#ff6b8182` 末尾是 `82`，正常不该命中。**本次报 `旧边=true` 的原因是**：
截图场景里 `_ga.color` 之外的路径…… 实测修正后为 false。
⇒ **教训**：断言正则**必须写成「颜色 + 后续固定片段」的完整形态**（`border:1px solid #[0-9a-f]{6}59;padding:1px 8px`），
只比 `\w+59` 会被相邻字符干扰，产生假阳性，白排查一轮。
