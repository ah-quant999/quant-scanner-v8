## 🔍 本地算法链 vs 云端算法链 审计结论（主人令一劳永逸）

**结论**：同一份 `run_algorithms.py` 在两端执行，**算法逻辑无差异，差异全在「运行环境」**；经一年内 TZ 偏移/emoji crash/pip 镜像空/mootdx 跨境/git reset 等事故沉淀，**云端 ubuntu-latest 全面胜出，本机禁止生产**。

|维度 | 云端 ubuntu-latest | 本机（Windows 家里/单位） |胜出 |
|---|---|---|---|
| **时区** | `TZ=Asia/Shanghai` 显式声明 | 系统默认 CST（依赖 Windows TZ） | **云端** |
| **emoji 编码** | `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1` | 3.13 默认 UTF-8（仍可能踩子进程 GBK） | **云端** |
| **数据源覆盖** | `MAHORO_COOKIE` / `ZSXQ_TOKEN` secrets 完整注入 | 本机 `data/.zsxq_token.json`（gitignore 手维护） | 平（本机略即时） |
| **数据源连通性** | 跨境 runner IP 慢（probe+重试兜底） | 中国 IP 直连快 | 本机采集略优（已封死） |
| **SKIP_MOOTDX** | `=1`（云端走 akshare） | 默认走 mootdx/baostock（曾踩"黑名单用户"） | **云端** |
| **推送链路** | `V8_PUSH=1` + `api_push_raw` Contents API 直推 main | 本机不推数据 | **云端远优** |
| **兜底重试** | 6 次指数退避 + 双镜像兜底 + GitHub API 同步源码 | 无 | **云端远优** |
| **双机一致性** | 主站 = 唯一权威；本地镜像同步对齐 | 本机跑过会**分叉主站**（主人 8/20 截图根因） | **云端远优** |
| **合规/护栏** | 无需（本来就不该跑） | `check_cloud_only()` 已封死 9 脚本 | **云端** |

### 云端「更先进」的具体证据（一年内事故沉淀）
1. **TZ 偏移**：ubuntu 默认 UTC → `update_time` 整体偏 8h → 前端「更新于」错一个时区。**云端已修**（显式 `TZ=Asia/Shanghai`）。
2. **emoji UnicodeEncodeError crash**：cn runner 默认 GBK → `print("📅✅")` 直接抛异常 → 整条算法链 0 执行。**云端已固化 `PYTHONIOENCODING=utf-8`**。
3. **pip 镜像拿空索引**：清华镜像在境外 IP 偶发空 → `|| true` 吞失败 → 整链死。**云端已改为官方 PyPI 优先 + 双镜像兜底 + import 实证校验**。
4. **mootdx 跨境 timeout**：云端无通达信接口，`SKIP_MOOTDX=1` 切 akshare。**本机默认走 mootdx**，你之前 `cockpit_backtest_now.py` 本地跑 baostock "黑名单用户"就是这个。
5. **git fetch 被 reset**：cn 自托管 runner 拉源码失败。**云端直接走 Contents API 同步源码**（带 sha 校验防截断）。
6. **推送覆盖防护**：云端有 `bridge_raw_data.py` 防 raw_data 内部改名断点、ALGO_TRACK `?v` 缓存戳同步。**本机裸跑无防护**。
