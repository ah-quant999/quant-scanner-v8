### P0-1 `v8_build_deploy.yml`：index.html 被静默盖回（**第三次复发根治**）

删除**主路径 + 重试路径**两处「备份 → reset → 盖回」：

```yaml
- if ! git diff --quiet -- index.html; then
-   cp index.html /tmp/index.html.manual
-   git reset --hard FETCH_HEAD
-   cp /tmp/index.html.manual index.html
- else
-   git reset --hard FETCH_HEAD
- fi
+ git reset --hard FETCH_HEAD
```

**为什么原写法必错**：该 `if ! git diff --quiet -- index.html`
在 CI 里**恒为真**（本步之前 `guard_v6_memo.py` / 选择构建 / `update_v8.py` 已改过 index.html）
⇒ 走 then 分支 ⇒ 备份到的却是 **checkout 时刻（陈旧）** 的内容
⇒ 若本 run 期间远端有新 push，`FETCH_HEAD` 前进、reset 拿到新内容，**随后被陈旧备份盖回**
⇒ 下一句 commit 的 parent 已是最新远端，push 天然 fast-forward
⇒ **无冲突、无告警地覆盖他人前端改动**。

**三次实证**：09-18 21:42 `149d5a2a30`｜09-19 07:22 `df63f016d1`｜09-19 07:24 `2acd970321`（另一趟 run 恢复）。
**铁证**：`df63f016d1` 的 index.html 内 `var BUILD = "8164d8f62"`（= 被覆盖那笔的 sha，说明 HEAD 已是新提交）
但正文无该提交的新增块 ⇒ 磁盘文件 ≠ `FETCH_HEAD` 那份。

### P0-2 `v8_build_deploy.yml`：gate 闸门**只判时钟、不判交易日**

原判据只有时钟窗（9:25-11:30 / 13:00-14:59），**无星期/交易日维度**。
**实证（我方 11:55 档，全天 28 个 run）**：唯一被判 `trading=true` 的 `#7073`（10:34:05）
**正是唯一 `build=skipped` 的那个**；把原判据逐 run 复算与 build 真实结论比对 = **28/28 一致**
⇒ 排除偶发/并发/超时，这是判据自身的确定性行为。

**危害**：① 非交易日该窗内的 push 拿不到 `update_v8` 重建与部署；② 主人「周末手动跑更新和部署」
**手动派发时也被 skip**（build 的 `if` 白名单含 `workflow_dispatch`）⇒ 诉求直接落空；③ run 顶层全绿掩盖以上两点。

**修复**（新增 `td` + `td_run` 两步，`t` 步叠加两层短路）：
```yaml
outputs:
  trading: ${{ steps.t.outputs.trading }}
  is_trading_day: ${{ steps.td_run.outputs.is_trading_day }}   # 🆕
steps:
  - id: td            # 🆕 sparse checkout 交易日历依赖
    continue-on-error: true
    uses: actions/checkout@v4
    with:
      ref: main
      sparse-checkout: |
        algorithms/check_trading_day.py
        v8_date.py
      sparse-checkout-cone-mode: false
  - id: td_run        # 🆕 复用既有日历
    continue-on-error: true
    run: python algorithms/check_trading_day.py || true
  - id: t
    run: |
      TH=...; TM=...
      DW=$(TZ=Asia/Shanghai date +%u)      # 🆕 1..7
      TR=0
      if {...时钟窗...}; then TR=1; fi
      IF_TD="${{ steps.td_run.outputs.is_trading_day }}"
      if [ "$DW" -ge 6 ]; then TR=0; fi              # 🆕 短路一：周末
      if [ "$IF_TD" = "false" ]; then TR=0; fi       # 🆕 短路二：非交易日
      echo "trading=..." >> "$GITHUB_OUTPUT"
      echo "is_trading_day=${IF_TD:-unknown}" >> "$GITHUB_OUTPUT"   # 🆕
```

🔴 **安全边界（务必知悉）**：日历步骤失败 ⇒ 输出为空 ⇒ `[ "" = "false" ]` 为假
⇒ **保持原时钟判据不降级**。这是刻意设计 —— 否则工作日盘中一旦日历接口抖动，
全量 build 会在盘中开跑，**复发 2026-09-03 的盘中风暴**（该风暴正是本闸门当初要根治的对象）。
