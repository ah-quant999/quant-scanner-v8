## 二、根因（B）——「某模块特立独行」

全站**五族子页签**，**只有 `.obs-tab` 一族没有高亮 CSS**：

| 子页签类名 | 高亮 CSS | 位置 |
|---|---|---|
| `.tab` | `.tab.active{color:var(--cyan);border-bottom-color:var(--cyan)}` | L135 |
| `.rc-tab-btn` | `.rc-tab-btn.active{background:...}` | L2908 |
| `.ul-tab` | `.ul-tab.active{background:...}` | L7348 |
| `.lg-tab` | `.lg-subtabs .lg-tab.active{background:var(--cyan)}` | L7357 |
| **`.obs-tab`** | ❌ **不存在** | —— |

而 `__obsSwitch()` 只做 `classList.remove('active')` / `add('active')`，
两个子页签的**颜色 + 下划线是渲染时用行内样式写死的**：

```js
// 修复前（__renderObsPlatform）
onclick="window.__obsSwitch(this,'macro')"
  style="...;color:' + (_act==='macro' ? '#34d399' : 'var(--sub)')
         + ';...;border-bottom:2px solid ' + (_act==='macro' ? '#34d399' : 'transparent') + '..."
```

⇒ **行内样式优先级高于类选择器**，切类名根本改不动横杆：内容 pane 切了、按钮外观不动。
这解释了主人看到的「点开的是大盘观测，绿色横杆还在宏观观测」。

**顺带查出的次生缺陷**：原实现是「先全部 remove，再给**入参 btn** 加」——
`__obsSwitch(null, tab)` 时**无人高亮**（btn 为空则一个都不加）。

## 四、⚠️ 本次踩到的两颗地雷（务必记住）

### 地雷 1｜本地基线是「旧缓存戳」——直接推会回退

开工时本地 `index.html` 的 `?v=1789427268` / `BUILD "7d3f31f79"`，
而远端 tip 已是 `?v=1789431724` / `BUILD "f6b0df234"`。
**归一化比对（把 `?v=` 与 BUILD 抹平）会显示 +0/-0，看起来「完全一致」——
但那只是把差异抹掉了，并不代表可以拿本地当基线推。**

> **铁律**：推前必须 `git ls-remote` 取最新 ref → `git show <tip>:index.html` 作基线，
> **禁止**用工作区文件当基线。本次改为「以最新 tip 为底重打补丁」，缓存戳/BUILD 一字未动。

### 地雷 2｜CRLF 归一化方向写反 → 静默产 `\r\r\n`

`logic.html` 是全仓唯一纯 CRLF 文件。我第一次写：
```python
s = raw.decode('utf-8')      # 此时仍含 \r\n
s = s.replace(...)           # 打补丁
out = s.replace('\n','\r\n') # ❌ 每个 \n 都变 \r\n ⇒ \r\n 变 \r\r\n
```
**症状极其隐蔽**：`CRLF 计数不变、bareLF 仍为 0**，只有字节数悄悄多了 8640
（≈ 8664 个 `\r`）。我是靠「字节数对不上」才发现的。

> **正确写法**：先 `s = s.replace('\r\n','\n')` 归一化，处理完再 `s.replace('\n','\r\n')`。
> **必加断言**：`b'\r\r' not in data`、`CRLF 数 == 基线 CRLF 数`、`bareLF == 0`。
