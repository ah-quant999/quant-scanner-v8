## 二、根因（均为实测，非推断）

### ① 字号
概念热力图 `titleFz 13/12/11/10 · fz 11/10/9/8`；行业树图 `titleFz 15/13/12 · pctFz 13/11/10`
⇒ **概念整体小 2px**。

### ② 符号写法
旧写法把「加号」散落在多处三元拼接：

```js
const netTxt = (it.net>0?'+':'') + fmt(it.net);        // 概念
h += '...' + (pct>0?'+':'') + fmt(pct) + '%';          // 概念 + 行业
```

两处隐患：
- **叠号风险**：若上游值已带符号，拼接会产出 `++`；
- **不可辨**：负数在小字号下与正数难分。

**另一实锤缺陷（放大截图确认）**：数值行无 `white-space:nowrap`，父级 `overflow:hidden` 会把
`+11.78亿` **硬切成 `+1.78亿`** —— 十倍量级显示错误。这同时解释了主人说的
「有连 + 号都没」（窄块里 `+` 被裁掉）。

> 补充实测：`origin/main:data/CONCEPT_RANKING.js` 共 100 项，**负值项 = 0**，
> 字段类型全为 number（无字符串带符号项）⇒ 叠号并非来自数据类型，而是**渲染层截断 + 小字号**。

## 三、修法

### ①② 概念热力图 + 行业树图
新增 **`fmtSigned()` 单一真源**（两处作用域各一份，因是两个独立 IIFE）：

```js
function fmtSigned(v){
  if(v==null||isNaN(v)) return '--';
  var n=Number(v), a=Math.abs(n).toFixed(2);
  if(n>0) return '+'+a;
  if(n<0) return '-'+a;
  return '0.00';
}
```

**先取绝对值再补一个符号** ⇒ 结构上不可能产出两个符号。

字号档位：

| px | 概念·旧 | 概念·新 | 行业·基准 |
|---|---|---|---|
| >110 | 11 / 13 | **13 / 15** | 13 / 15 |
| >80 (>75) | 10 / 12 | **11 / 13** | 11 / 13 |
| >55 | 9 / 11 | **10 / 12** | 10 / 12 |
| 其余 | 8 / 10 | **9 / 11** | — |

数值行加 `white-space:nowrap`；净额行字号加下限 `Math.max(9, fz-1)`。
