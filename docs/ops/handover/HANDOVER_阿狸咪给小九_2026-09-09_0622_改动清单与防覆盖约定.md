## 二、⚠️ 防覆盖：三层机制（已逐条查证，非推测）

### ✅ 第 1 层：云端 build **不会**覆盖 index.html（安全）

`.github/workflows/v8_build_deploy.yml` **L195–197 与 L305–307**（主路径 + 重试路径均有）：

```bash
cp index.html /tmp/index.html.manual      # 先备份人工版
git reset --hard FETCH_HEAD
cp /tmp/index.html.manual index.html      # reset 后立即还原
```

→ 云端 build 只重算 `data/*.js` 的 `?v`，**index.html 的人工改动受保护，不会被洗掉**。

### ⚠️ 第 2 层：你本地 `git push` **会**覆盖（真实风险）

你昨晚走的是 **Contents API 单文件直推**（本地树落后 main 若干提交）——这条路本身安全（409 自动重取 sha）。
**但如果你改用 `git push`，且本地 index.html 落后于 `b55402a81`，会直接覆盖我的改动。**

**防覆盖操作（任选其一，按你的习惯）**：

- **走 Contents API（你昨晚的方式，推荐）**：直推前先 `GET /repos/…/contents/index.html` 取最新 `sha`，带上 sha PUT；409 就重取重推 —— 你脚本里已有这个机制，**保持即可**。
- **走 git**：先 `git fetch origin main && git pull --rebase`（或 `git rebase FETCH_HEAD`），确认本地包含 `b55402a81` 再改再推。
- **冲突时**：index.html 逐处手工合并，**禁用 `git rebase -X theirs`**（曾静默丢本地改动）。

### ⚠️ 第 3 层：`?v` 缓存戳会被自动对齐（无需你管）

`v8_cache_buster_reconcile.yml` 每 15 分钟自动对齐 `index.html` 的 `?v` 与 `data/*.js` 实际内容。
→ 你我只管改内容，**不要手工刷 `?v`**（昨晚我刷过 3 个，属多余动作，已停）。
