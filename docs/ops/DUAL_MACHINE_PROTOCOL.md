## 0. 总则：自主决策，不烦主人

- 🔴 **只在「不确定主人意图 / 方向」时才问意见**；其余一律用**专家的科学方法**自行裁定、直接执行。
  - 判据：指令明确、有既定协议/历史结论、或属常规技术决策 ⇒ **不问，直接做**。
  - 仅当指令存在真实歧义、或动作不可逆且方向不明时，才问**一个问题**并给选项，禁逐次请示。
- 🔴 **发现问题 → 一劳永逸修复**：根因级修复，按实现特征**全仓扫描**确认无第二处同类缺陷（「我改过的那份对了」≠ 修好），禁半截修复。
- 🔴 **修好 + 审计通过 → 直接上线**：收尾**禁止反问「要不要上线 / 等你说上线」**。取消的是等待，不是审计。
- 🔴 **全程中文**：与主人所有交互、所有专家回复、所有交付文档一律使用**简体中文**（说明文字、报告、交接件均中文；代码标识符除外），**禁英文混答**。
- 🔴 **不许说谎 / 不查不张口**（第二铁律，细则见 `~/.workbuddy/MEMORY.md`）：结论必带 1 句举证（命令/路径/sha/update_time）。

## 2. 改后三件套（收尾必做，禁等主人问）

> 每次改动仓库内容（前端 / 算法 / workflow / 守卫脚本 / 数据管线）收尾前必须跑完；任一项未跑须在回话里**显式说明**，禁只回「做了」。

### 2.1 一、审计
- 离线复现全套 CI 门禁（`v8-offline-ci-gate-repro`）：`pre_deploy_audit` 全项 + `align_logic_ops` + `v8_verify_layer_parity`，全绿。
- **结论必须绑定 `HEAD=<sha>`**；跨 tip 比数字必误判（本机 clone 滞后会假绿/假红）。
- 纯文档 / 协议类改动无代码门禁影响 ⇒ 标注「N/A 代码门禁」，仍须**逐字节自证推送内容**。

### 2.2 二、四方对齐
同一功能在**四处口径必须一致**：
1. **云端** workflow cron / 派发配置
2. **双机**任务时窗（小九白天 7:45–17:45 / 阿狸咪夜间·周末 18:00–次日 7:30+周末）
3. **运维页**（index.html 运维面板）
4. **逻辑详解页**（logic.html / 逻辑说明页）

- 任一处改动 ⇒ 其余三处同步核验；口径冲突 ⇒ 以主人定式 / 本协议为准并回写本节。

### 2.3 三、推仓入库防覆盖 + 和另一台机交接
- 推送走 **Git Data API**：实时重取远端 tip → `base_tree` 只列变更路径 → `force:false` → 推后**逐字节自证**。
- **防覆盖**：推前比字节、以远端真身为基底重放补丁；`[10/10] index 核心标记守卫`（`docs/ops/index_protected_markers.txt`）是部署期防线，**有意删功能必同步删清单行**。
- **交接**：件入 `docs/ops/handover/`，命名 `<日期>_<时间>_<发送方>给<接收方>_<主题>.md`（时间**实取**北京时间），含 ① ② 审计原始输出 + 改动清单 + 待对方应用项 + 可跑复核命令（不给本机私有路径）。
