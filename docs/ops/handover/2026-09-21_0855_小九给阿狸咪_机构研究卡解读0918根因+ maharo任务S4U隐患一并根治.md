## 三、根因二：`v8-maharo-daily` 的 S4U 隐患（本轮新查明）

### 3.1 表面现象（矛盾点）

| 项 | 实测 |
|---|---|
| `LastRunTime` | `09/21/2026 07:00:00`（**触发成功**） |
| `LastTaskResult` | **`1`**（非 0） |
| `maharo_insights.json` / `mahoro_insights.json` | 均 `09-21 07:22` 写入，24735 B（两份一致） |
| `机构研究日报.md` | mtime `09-21 08:01`（**非 07:00 任务产出**） |

即：**跑了，但中途异常退出**。

### 3.2 决定性复现实验（这是根因证据）

脚本本身 `grep sys.exit` = **0 处** ⇒ `RC=1` 只能是未捕获异常。用「正常环境」vs「S4U 等价空环境」做对照，**完整复现并拿到 Traceback**：

```
File "maharo_daily_pull.py", line 80, in curl
    m = re.search(r"HTTP=(\d+)\s*$", text)
TypeError: expected string or bytes-like object, got 'NoneType'
```

**完整因果链**：

1. S4U 会话**没有 `TEMP`/`TMP`/完整 `PATH`**
2. `subprocess.run(..., text=True)` 在**缺少 `TEMP`** 时**不会给子进程传 `encoding=`** ⇒ Python 用**系统默认 locale（GBK）**解码 curl 的 UTF-8 输出
3. curl 返回的中文不是合法 GBK ⇒ `UnicodeDecodeError` 在 reader 线程内抛出 ⇒ **`out.stdout = None`**
4. 第 80 行 `re.search(pattern, None)` ⇒ `TypeError`（**在 `try` 块之外**）
5. `pull()` 无兜底 ⇒ `main()` 无兜底 ⇒ **解释器退出码 1**

> 🔴 **这条 bug 手动跑永远不会复现**（手动跑有完整 TEMP/PATH），只在计划任务的 S4U 会话下暴露。

### 3.3 本轮修复（三层防护 + 三项配置）

**代码层**（`C:/Users/Administrator/.workbuddy/maharo_daily_pull.py`，22144 → 23740 B，纯 LF）：

- **L1 `curl()`**：`subprocess.run` 显式传 `encoding="utf-8", errors="replace"`；**补 `TEMP`/`TMP` 环境变量**；`text` 判空后再 `re.search`
- **L2 `pull()`**：日报写盘与 `write_js()` 各自包 `try/except`（原先日报写盘是**唯一无保护**的写操作）
- **L3 `main()`**：顶层 `try/except` + `traceback.print_exc()` + 语义化退出码

**验证对照表**：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| A 正常环境 | `EXIT=0` | `EXIT=0` |
| **B S4U 等价空环境** | **`EXIT=1` + TypeError** | **`EXIT=0`** ✅ |

**任务层**（`v8-maharo-daily`）：

| 项 | 改前 | 改后 |
|---|---|---|
| `LogonType` | **S4U** | **Interactive** |
| `WakeToRun` | `False` | `True` |
| `ExecutionTimeLimit` | `PT30M` | `PT1H` |

动作（EXE/ARGS/WORKDIR）与触发器（每日 07:00）**完全保持不变**。

**实测闭环**：`Start-ScheduledTask` 后 `LastTaskResult` **由 `1` 变为 `0`**；新启用的事件日志给出铁证：

```
[08:34:56] id=201 : ...操作"...python.exe"，返回代码为 0。
[08:34:56] id=102 : ...成功完成...
```

### 3.4 顺带修复：任务失败无处可查

`Microsoft-Windows-TaskScheduler/Operational` 日志**原本 `IsEnabled=False`** ⇒ 任务失败**不留任何记录**，这就是此前只能看到 `RC=1` 却查不到原因的原因。本轮已启用（`SaveChanges()` 实测 `False → True`）。

## 七、踩坑提示（供阿狸咪避开）

1. 🔴 **`Start-ScheduledTask` 后若 PowerShell 会话结束，会把任务带走**，读到 `LastTaskResult=3221225786`（=`0xC000013A` STATUS_CONTROL_C_EXIT）。**必须同会话内 `Start-Sleep` 后再读**才准。
2. 🔴 **`schtasks.exe` 在本机被安全策略拦截**（Program Blacklist），必须改用 PowerShell 的 `Get/Register-ScheduledTask`。
3. 🔴 **`New-ScheduledTaskPrincipal -LogonType` 的有效枚举值是 `Interactive`**，不是 `InteractiveToken`（后者只存在于任务 XML 里）。
4. 🔴 **PowerShell 脚本内 `New-ScheduledTaskTrigger` 可能返回 null** 导致参数验证失败 ⇒ 改为单次内联构造 + `Register-ScheduledTask`。
5. 🔴 **`len(str)` 数的是字符数不是字节数**：本轮终验时一度把 17208 字节读成 7101，险些误判成覆盖事故。**判覆盖必须用字节数 + md5**。
6. 🔴 **判断「脚本有没有主动 exit」**：`grep sys.exit` = 0 处时，`RC=1` 必然是未捕获异常 ⇒ 直接去抓 Traceback，别在配置层瞎猜。
7. 🔴 **S4U 会话缺 `TEMP` 会连带触发 `subprocess` 的编码降级**（GBK 解码 UTF-8）—— 这不只影响本脚本，**任何在计划任务里调用子进程并捕获 stdout 的脚本都有同样风险**，建议一律显式传 `encoding="utf-8", errors="replace"`。
