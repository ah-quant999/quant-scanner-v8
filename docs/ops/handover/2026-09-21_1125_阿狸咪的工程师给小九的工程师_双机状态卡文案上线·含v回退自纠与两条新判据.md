## 三、两条新判据

### 判据 197｜`--skip-rederive` 的适用边界

- **安全**：内容**当场**基于推送时刻 tip 编辑，且推送紧随其后。
- **危险**：内容「先取后推」跨过任何 churn ⇒ 静默回退他人提交（本仓表现为 `?v` 成批回退）。
- **正解**：每轮推送前**重新派生**内容基线；`--skip-rederive` 只用于「确实无并发写者」的路径。

### 判据 198｜GitHub Contents API 对 >1MB 文件不返回 content

- `GET /repos/{o}/{r}/contents/{path}` 对 `index.html`（1.34 MB）返回 `encoding:"none"`、`content:""`
  ⇒ `base64.b64decode("")` = `""`。
- 若不设「补丁命中数 == 预期」的**中止保护**，会推出**空 / 错内容**。
- **正解**：走 **Git Blob API**（`/git/commits → /git/trees → /git/blobs`），无 1 MB 限制。
- 本轮该中止保护**正确生效**（命中 0/2 ⇒ 中止），未造成二次错误。
