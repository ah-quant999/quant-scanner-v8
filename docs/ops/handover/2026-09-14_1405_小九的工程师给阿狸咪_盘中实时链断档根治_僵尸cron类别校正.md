## 三、修复（两层 + 一层降级兜底）

### 修复 1 · 类别判定加「僵尸 run 时刻校正」（治本）

`🕐 确定抓取类别` 步骤：cron 分支由「直接 echo GITHUB_OUTPUT」改为「变量式 + 统一校正后输出」。

```bash
case "$CRON" in
  "25 0 * * 1-5")         CAT="premarket"; LB="盘前" ;;
  "*/20 1-3,5-6 * * 1-5") CAT="intraday";  LB="盘中(云端原生种子)" ;;
  "20 9-11 * * 1-5")      CAT="post_close"; LB="盘后" ;;
  "0 1 * * 0,6")          CAT="all";       LB="全量兜底(周末周度)" ;;
  *)                      CAT="all";       LB="兜底(未匹配cron $CRON, 走all)" ;;
esac

# 🛡 僵尸 run 时刻校正
_HM=$(python3 -c "...n.hour*60+n.minute" 2>/dev/null || echo 0)   # 取时失败兜底 0
if [ "$CAT" = "premarket" ] && [ "$_HM" -ge 575 ]; then            # 已过 09:35 ⇒ 必为僵尸
  if   [ "$_HM" -le 905 ];  then CAT="intraday";   LB="僵尸盘前档·按实际时刻重判(盘中)"
  elif [ "$_HM" -le 1290 ]; then CAT="post_close"; LB="僵尸盘前档·按实际时刻重判(盘后)"
  else                           CAT="all";        LB="僵尸盘前档·按实际时刻重判(深夜→all)"
  fi
fi
echo "category=$CAT" >> "$GITHUB_OUTPUT"
echo "label=$LB"
```

- **正常盘前 08:25**：`_HM≈505 < 575` ⇒ 判 premarket，**行为零变化** ✅
- **降级兜底**：python 取时失败 ⇒ `_HM=0` ⇒ 不校正、保持原判定，**绝不因取时异常阻断抓取**

### 修复 2 · 自接力放宽条件（保底，杜绝整链断裂）

```yaml
# 旧（太脆：一旦类别误判，整条链当场死）
if: always() && steps.gate.outputs.skip != 'true' && steps.cat.outputs.category == 'intraday'

# 新（窗口判断交回脚本自身 in_win()，09:38-11:32 / 12:58-15:05）
if: always() && steps.gate.outputs.skip != 'true' && steps.cat.outputs.category != 'post_close' && steps.td.outputs.proceed != 'false'
```

- 接力脚本**本身自带 `in_win()` 窗口判断**，非窗口会静默退出 ⇒ 放宽 if 后**语义等价且不再断链**
- `post_close` 档仍不接力（有独立盘后链，避免重复派发）
- 同时接入**交易日历闸门** `steps.td.outputs.proceed`，节假日不接链
