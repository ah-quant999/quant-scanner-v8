## 四 本回合的两条重要发现

### 4.1 🔴🔴 「周末假红」根因：法定「补班日」被误当 A 股交易日

**权威源交叉（三处，全部指向「周末休市」）**：

| 来源 | 口径 |
|---|---|
| `algorithms/fetch_lhb.py` → `ak.tool_trade_date_hist_sina()` | 新浪官方 A 股交易日历，**排除全部周末** |
| `v8_date.py` | 优先 `fetch_lhb.is_trading_day`，fallback 才 `weekday()<5` |
| `v8_stage_gate.py` | 经 `v8_date` 判 2026-09-20（周日）= 非交易日 |

**A 股史上从未在周末交易**；法定「补班日」只调整企业与机关作息，与证券市场无关。
`v8_health_check.py` 的 `_MAKEUP_DAYS_2026` 是**错的那一侧**，且造成三重后果（见 2.3）。

> **这是根治而非补丁**：没有去调单卡 `max_age`，也没有给卡加豁免，而是修掉了共同根因。
> **凡「交易日/休市」判断，唯一权威 = `fetch_lhb.is_trading_day`（经 `v8_date`）；请勿再写第二套日历。**

### 4.2 🔴 「产物已生成」≠「产物已被消费」

截至 **2026-09-20 15:1x CST** 实测：

| 项 | 值 |
|---|---|
| `raw_data/backtest_expectancy.json` `meta.generated` | **2026-09-20 10:41:42**（`excess5` 齐备，新口径） |
| 同文件 `sig_jinzuan` | `excess5=+0.532` / `edge5=+0.628` / `edge10=+7.907` / `n_on5=128` |
| `data/FINAL_RECOMMEND_DATA.js` `update_time` | **2026-09-20 09:50:20**（**早于** 10:41） |
| 同文件 `signal_edge.source` | `backtest_expectancy@2026-09-19 18:18:26`（旧产物） |
| 同文件 `signal_edge.effective` | `{jinzuan:8.676, chan:4.647, trend:-7.593, jigou:-9.457}`（旧口径量级） |

⇒ **口径改造代码已正确落地**（`algorithms/final_recommend.py` 读 `excess5`，且
`SIGNAL_EDGE_DEFAULT` 已换成 `{0.532, 0.759, -1.532, -0.660}`），
但**最后一次 D 批跑在上游产物生成之前** ⇒ 线上最终推荐仍是旧口径 ⇒ **必须重跑 D 批**。

**通用判据**：`update_time(消费端) < generated(上游)` ⇒ 口径改造未生效。
